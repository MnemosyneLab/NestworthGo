# Nestworth 桌面交互改进计划

第一、二批已实施。第三批待实施。依据 2026-11-13 在 `a0eec4f6` 上用空账本和多币种合成账本进行的交互审查。以下按实施顺序排列。

## 第一批 · 开始记账、补齐数据、确认变动

- [x] **开始记录历史。** 首个账户保存后和首页待处理区都提供「开始记录历史」，直达日期和时区确认。说明从今天开始会以已录入余额作为起点。历史未开始时，首页只显示一条引导，去掉「未知标的」提示。
- [x] **从缺口直接补录。** 首页优先显示需要操作的前置条件，把受影响的快照和日期放在明细中。点击具体缺口的「补录」直接打开表单，带入标的或币对及有效日期。汇率输入旁显示 `1 AUD = [输入值] SGD` 这样的等式，历史图和预览都显示当前方向。补录后回到原问题并更新状态。历史缺口卡片优先显示补录、查看证据或检查覆盖等相关动作，最新行情刷新放在行情管理区。
- [x] **让预览可以独立核对。** 在确认按钮附近列出操作、日期、账户和币种，按受影响的余额或持仓显示「变动前 → 本次变化 → 变动后」。转账和换汇分别展示两端，交易展示相关金额和数量。以同一次后端预览为准，保留现有审计轨迹。

## 第二批 · 讲清金额和覆盖状态

- [x] **总览与可用资金。** 在各自金额旁标明当前估值、历史覆盖和可用规则的状态。可用资金直接显示已确认金额及待补规则项数，点击可筛到相应条目。缺失数据继续显示为未知。
- [x] **收益分析与资产变动。** 用可见文字说明收益率按多少个可计算日得出，区分缺估值与有金额但无法计算收益率的日期。把查看缺口入口放到相关结果旁。资产变动图保留所选时间范围，并标出无数据的日期。继续提供图表数据表。

## 第三批 · 减少操作和统一控件

- [ ] **首个账户。** 先选账户类型，再给出相关的机构和记录方式选项。把 `No matching institution` 改成明确的「无机构」选项，说明何时可以稍后添加。家庭只有一位成员时默认选中，允许修改。确认页显示机构、所有者、记录方式、币种和期初值。
- [ ] **账务记录。** 将交易类型按现金、投资、债务组织，从账户详情进入时优先展示该账户的常用操作。把起止日期、快捷范围和实际查询区间放在同一个筛选区，始终显示当前生效范围。
- [ ] **账户和持仓。** 在较窄窗口保留清楚的记账主按钮，把次级操作放在稳定位置。标的名称进入详情，展开按钮用于查看分账户持仓，更多菜单放行内操作。保留返回时的标签、筛选、滚动和键盘焦点。
- [ ] **待办、数据设置与 AI。** 说明待办页数据检查计数只涵盖近期事项，维护入口使用独立名称。数据设置里分清备份恢复、导出、历史重算和持续备份，从相关健康问题直达重算。AI 助手分别说明首次未配置、已禁用和原模型失效的状态，提供「打开 AI 设置」。
- [ ] **视觉和无障碍。** 沿用现有配色、组件与金额层级，统一页面主操作、状态标签和帮助文字的位置。汇率历史去掉重复标题，改用汇率图例并修正末端日期裁切。给图标按钮提供可读名称和可见焦点，给 `◇` 等覆盖提示加可见文字，检查日期控件和抽屉的键盘顺序。

## 验收

1. 用独立空账本创建家庭和首个账户。从保存后及首页进入历史起点，核对日期、时区和起始余额，重启后确认历史状态。
2. 用多币种合成账本覆盖缺历史汇率、缺价格和快照不完整。验证一键打开补录、币对方向、日期、保存后状态回查，以及可用规则和分析覆盖的显示。
3. 用合成数据验证收入、支出、转账、换汇和交易的预览及保存。核对前后余额或数量，确认详情返回能恢复列表上下文和焦点。
4. 复用共享控件，为实际交互补回归覆盖。运行相关前端检查及涉及的 Go 测试。在宽窗和窄窗、浅色和深色、简中和英文下复查，用键盘和 VoiceOver 走关键路径。浏览器与原生 macOS 验收分别记录，原生测试按[隔离运行流程](../development/local-workflow.md#isolated-native-development-qa)使用合成账本。
