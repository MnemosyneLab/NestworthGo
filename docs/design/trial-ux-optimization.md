## 已拍板的产品规则

这些规则约束后面所有条目，实现时不要再展开成新的产品分叉。

1. **投资组合按成分，不按账户。** 有持仓（Holding / 带 `instrumentId` 的估值成分）就算投资；现金不算。银行账户里的黄金要进组合；券商账户里的现金不进组合。账户上不再出现「计入投资组合」勾选。
2. **换汇、买卖、转账金额改为手动计算。** 用户可随意填写一侧或两侧；空着或为 0 的一侧由「计算」按行情/汇率补上。同币种转账转入金额只读，始终等于转出。
3. **市场数据两个动作。** 「刷新缺失/过时」只拉没有本地数据、或超过缓存有效期的目标；「强制刷新全部」忽略时效。估值需要的汇率对默认走提供方，不必先点「使用提供方」。
4. **缓存有效期是全局设置。** 可选 1 小时、3 小时、12 小时、24 小时，默认 12 小时。只约束提供方行情/汇率的自动跳过，不阻止强制刷新。
5. **日期用 shadcn 日历弹层，时间用 24 小时时/分选择。** 不跟操作系统 12 小时制走；不用原生 `type="date"` / `type="time"`。

`include_in_net_worth` 和 `include_in_liquid_assets` 仍是账户级开关，本方案不改。

## 1. 默认机构与分组

**问题：** 初始化只建家庭和成员。创建账户必须自己建机构，分组也是空的。

**目标：** 第一次使用就有可改名、可换图标的默认机构与分组；新建账户预选它们。

**方案：**

- 完成 Onboarding 时各插入一条普通记录，不是特殊实体：
  - Institution：名称随界面语言（`zh-CN`「默认机构」，`en` “Default institution”），`institutionType=other`。
  - Group：名称随界面语言（`zh-CN`「默认分组」，`en` “Default group”）。
- 用户可在 Directory 里改名、换图标、归档。不增加 `is_default` 列。创建账户预选 `sort_order` 最小的未归档机构/分组（种子会排在最前）。
- 升级已有数据库：启动时若未归档机构数为 0 则补建机构；分组同理。已有数据不重复插入。
- 创建向导第一步预选该机构，仍可改选或「新增机构」。详情步预选该分组。提交时带上这两个 id，不再默认为空。

**验收：** 新家庭 Onboarding 后 Directory 各有一条；新建账户表单已选中它们；改名后新账户仍选中改过名的那条。

## 2. 缺汇率时仍显示原币金额

**问题：** 欧元现金 100 EUR，没有 EUR 汇率时，账户列表和简单账户详情连 100 EUR 都不显示。

**目标：** 原币始终可见。主币种价值在有汇率时显示，没有时明确说待换算。

**方案：**

- 估值已经把原币写在 component `nativeAmount` / 账户 `latestValue` 上。缺 FX 只应清空 `baseValue`，不得把原币当成「无价值」。
- 账户列表右侧主行显示原币（`€100.00`）。有主币种价值时第二行或右侧附列显示主币种；没有则显示「待换算」一类文案，不要用「无价值」覆盖原币。
- 简单账户详情标题金额同理：原币优先，主币种次之。
- 复合账户现金行已有原币时，缺汇率仍显示原币，可加「缺汇率」标记。

**验收：** 主币种 CNY、现金账户 100 EUR、无 EUR 汇率时，列表和详情都能看到 €100.00，而不是空白或「无价值」。

## 3. 更新余额的历史句子

**问题：** 300→320 显示「将钱包更新为 ¥20.00（对账）」。20 是差额，文案却像新余额。

**目标：** 读者能看出新旧余额，不会把差额当成新值。

**方案：**

- `value_update` 的 effect 仍存差额（账本语义不变）。
- 列表句子改为同时说出新值。优先：「将 {账户} 更新为 {新值}（对账）」。新值 = 当前余额（预览/记录后的 endpoint），不是 delta。
- 若列表 DTO 暂时拿不到更新后余额，退一步：「{账户} 增加/减少 {差额}，更新后 {新值}」。不要单独说「更新为 {差额}」。
- Overview 近期活动与 History 共用 `activitySentence`。

**验收：** 300→320 显示更新为 ¥320.00，或等价的「增加 ¥20.00，更新后 ¥320.00」。不再出现「更新为 ¥20.00」。

## 4. 所需汇率可直接刷新（与第 9 条一起）

**问题：** 新增币种后，「刷新所需汇率」会跳过未配置提供方偏好的币对，只能先点「使用提供方」。

**目标：** 估值需要的汇率对，点「刷新缺失/过时」就能拉。不必先配置来源。

**方案：**

- 账户余额、现金、持仓报价币种相对家庭主币种形成的币对，视为**估值所需**。
- 所需币对默认 `sourceKind=provider`，使用 Settings 里的 FX 提供方。首次刷新前若还没有 `FXPreference`，刷新路径自动写成提供方，不要让用户先点「使用提供方」。
- 市场数据页去掉作为前置步骤的「使用提供方」按钮。若仍需手动汇率，放到该币对的来源切换（提供方 / 手动），而不是阻塞刷新。
- 「刷新缺失/过时」包含：估值所需且（无报价或超过缓存有效期）的 FX，以及同样条件的提供方标的。手动报价标的仍跳过网络刷新。
- 非估值所需、但用户已保存的额外币对：只在「强制刷新全部」里更新，避免可选币对抢限流（沿用 required-before-extra）。

详见第 9 条按钮与缓存。

## 5. 日期与时间选择器

**问题：** 原生 `type="date"` / `type="time"` 又小又难看；时间跟随系统，可能是 12 小时制。

**目标：** 日期用现成日历弹层。时间永远 24 小时制，且不是原生 time input。

**方案：**

走 shadcn **Base UI** 版 Date Picker 的组合方式（[base/date-picker](https://ui.shadcn.com/docs/components/base/date-picker)），不要用同页的 Radix 版。本仓库已经用 `@base-ui/react`，不再引入 Radix。

参考例子里的 **Time Picker 不要照抄**：那一节仍是 `<input type="time">`，只是藏了时钟图标，系统 12 小时制问题还在。

新增共用控件，替换所有原生 date/time 输入（Record change 生效时间、History 筛选、标的手动报价日期，以及之后同类字段）。

**日期 `DatePicker`**

- 组成：`Popover` + `Calendar`。没有单独的 DatePicker 根组件。
- `Calendar` 用 [react-day-picker](https://daypicker.dev/)（shadcn `components/ui/calendar`）。`date-fns` 已在依赖里。
- 项目里还没有 `popover` / `calendar`，按 Base UI 变体补上并套现有 Button / Token 样式。不要 `npx shadcn add` 一整套无关组件；`Field` 不必加，现有 `Label` 即可。
- 点击触发按钮弹出月历；上月/下月、选中态清楚。`captionLayout="dropdown"` 可用。
- 一周起始跟随 Settings `week_start`。
- 按钮上的展示跟随 Settings `date_format`；提交值仍是 `YYYY-MM-DD`。
- 键盘：打开/关闭、方向键换日、Escape 关闭、Enter 确认（跟 DayPicker / Popover 默认行为）。
- History 生效时间：不可早于 Origin 当地日、不可晚于「现在」所在当地日（与现有校验一致）。

**时间 `TimePicker`**

- 永远 24 小时制。不使用原生 `type="time"`，不读操作系统 12 小时制，也不读 Settings `time_format`。
- 外观与日期按钮对齐（outline button）。点开后是时 `00–23`、分 `00–59` 两列（下拉或滚动列表），不要画钟面。
- 提交值仍是 `HH:mm`。Record change 仍把当地日期+时间交给后端做 Origin 时区转换。

**组合**

- Record change：日期 + 时间并排。
- 仅日期的筛选项/报价日：只用 `DatePicker`。
- Fix 流程保持原 `effectiveAt` 只读，不出现可编辑选择器。

**验收：** 系统为 12 小时制时，时间选择仍是 00–23。月历可换月、选中态明显。History 与报价日期都走新控件。没有 Radix 依赖，没有 `type="date"` / `type="time"`。

## 6. 换汇改为计算按钮

**问题：** 键盘输入时只有第一位数字会自动换算。

**目标：** 两侧金额用户自己填。需要时点「计算」，按当前汇率补空侧。

**方案：**

- 去掉卖出/买入之间的 `useEffect` 自动换算和 `fxDriver` 边输入边改。
- 卖出、买入都可编辑，允许空或 0。币种规则不变（不能相同；费用币种锁定为卖出币种）。
- 保留 `QuoteHint`：展示当前汇率、缺失时的更新按钮。计算用这份已加载的汇率，前端只做默认值，Preview/Record 仍由 Go 校验。
- **计算**规则：
  1. 两侧都空或都为 0：提示「请先填写卖出或买入中的一侧」，不改字段。
  2. 恰好一侧有正数、另一侧空或 0：用汇率填空侧。
  3. 两侧都有正数：不覆盖。用户已决定两边的数（实际成交可以不等于中间价）。
- 换了币种或刷新了汇率：不自动改金额。用户再点计算。
- 提交仍要求两侧都有正数。算完前 Preview 保持不可用。

**验收：** 连续输入 100 不会只按第一位去改另一侧。填 100 卖出、买入留空，点计算后买入为汇率结果。两侧都填时点计算，两边都不变。

## 7. 买入/卖出金额改为计算按钮

**问题：** 数量 × 行情自动填总额，同样只有第一下可靠，也容易在用户改总额时被覆盖。

**目标：** 数量和总额都可手填。点「计算」再用当前价格补空项。

**方案：**

- 去掉数量/行情变化时对 `gross` 的自动写入。
- 数量、总额都可编辑。费用仍为可选。币种仍锁定为标的报价币种。
- `QuoteHint` 保留（现价 + 更新）。
- **计算**规则：
  1. 有数量、总额空或 0、且有现价：`gross = quantity × unitPrice`。
  2. 有总额、数量空或 0、且有现价：`quantity = gross ÷ unitPrice`（数量小数位按现有 quantity 规则）。
  3. 两侧都有正数：不覆盖。
  4. 没有现价：提示去更新行情；手动报价标的走现有手动报价，不算提供方。
- 提交仍要求数量和总额都有。卖出仍要选中有数量的 holding。

**验收：** 改数量不会把用户刚填的总额改掉。只填数量再点计算，总额等于数量×现价。

## 8. 买入/卖出历史要有具体信息

**问题：** 列表只有「买入（本金）」「卖出（本金）」。明细其实已写入 `activity_trade_details`，列表没读回来；句子缺数量就退化成 kind，交易 reason 又固定为 `principal`。

**目标：** 一行能看出账户、标的、数量、总额、费用。

**方案：**

- `ListActivities` / `ListActivityPage` 读取并填充 `TradeDetail`（与 effects 一起）。
- `activitySentence` 用明细生成，例如：「在 {结算账户} 买入 {数量} {标的}，总额 {金额}」；有费用则「，费用 {费用}」。卖出对称。
- 列表不要再拼 `（本金）`。`ReasonPrincipal` 对买卖是内部分类，不是用户要看的原因。
- 账户名、标的名继续用现有 id→name map；缺失时用现有 unknown 占位。

**验收：** 一笔买入至少能看到账户、标的、数量、总额。有费用时句子里有费用。不再出现单独的「买入（本金）」。

## 9. 市场数据刷新与缓存有效期

**问题：** 没有「强制 vs 只拉过时」；新币种还被偏好配置挡住。有效期写死，不能调。

**目标：** 两个明确按钮 + Settings 里的缓存有效期。

**方案：**

### Settings

- 新增 `quote_cache_ttl`（名称可按现有 settings JSON 风格微调），枚举：`1h` / `3h` / `12h` / `24h`，默认 `12h`。
- 放在市场数据/提供方附近，说明：只影响「刷新缺失/过时」是否跳过本地提供方报价；强制刷新忽略此项；手动报价不走提供方刷新。
- 估值展示用的 freshness 标签与跳过刷新使用同一有效期，避免「设置 12 小时、标签却按 24 小时标过时」。

### 市场数据页按钮

| 按钮 | 行为 |
| --- | --- |
| 刷新缺失/过时 | 估值所需的提供方标的 + 估值所需 FX。无本地报价，或 `now - quotedAt` ≥ TTL，才请求提供方。仍在有效期内的标 `cached`/`skipped`，不打网络。 |
| 强制刷新全部 | 忽略 TTL，重拉所有提供方标的和已保存的提供方汇率（所需优先，额外币对在后）。 |

- 去掉「刷新所需汇率」和作为前置的「使用提供方」。
- 刷新结果列表仍用人名/币对，不用内部 target key。

### 后端

- 刷新目标构建时，估值所需 FX 即使还没有 preference 也不要 `skip`。
- `AppendProvider*IfChanged` 仍可避免写入相同价格；TTL 决定**要不要请求**，不是要不要展示。

**验收：** 12 小时内有本地 EUR 汇率时，「刷新缺失/过时」不请求该币对；强制刷新会请求。新建欧元账户后，不必点「使用提供方」，「刷新缺失/过时」能拉 EUR/主币种。改 Settings 为 1 小时后，1 小时内的报价会被跳过。

## 10. 概览近期活动移到最底部

**问题：** 近期活动在资产配置前面，主配置信息被挤到下面。

**目标：** 先看净资产和配置，活动放最后。

**方案：**

顺序改为：

1. 净资产 + 数据健康 / 下一步（现有双栏）
2. 资产配置：按类型、机构、账户类型、负债类型、成员、分组

不改数据源和活动条数（仍是 5 条）。

**验收：** 有账户和活动时，滚动到页底才是近期活动；配置块在它上面。

## 11 + 14. 投资组合：有持仓就算，现金不算

两条是同一条规则，一起改。

**问题：**

- 券商整户纳入时，结算现金也被算进投资。
- 银行账户默认不纳入，招商银行里的黄金因此不出现。
- 账户上还有「计入投资组合」勾选，用户还得理解一个整户开关。

**目标：** Portfolio 只表示投资持仓。与账户类型、机构类型无关。没有勾选。

**方案：**

### 计算

`Portfolio` / `PortfolioSnapshot`：

- 纳入：未归档、角色为资产的账户上，**带 Instrument 的持仓成分**（有市值或有缺失价都列出；缺失价标不完整，总额仍排除缺失项）。
- 排除：现金成分、简单账户的余额/人工总值、负债账户、已归档。
- 分配（按币种/国家/标的类型）只对上述持仓成分。现金桶不应出现在 Portfolio 分配里（现金仍在 Overview 资产配置里）。
- 不再用 `account.IncludeInPortfolio` 做过滤。

人工总值账户（例如一笔「养老金」总额、没有 Holding）**不进 Portfolio**。要进组合，就把标的建成 Instrument + Holding。这一点写在 Portfolio 页说明里。

### UI

- 创建向导、账户设置去掉「计入投资组合」勾选和相关警告。
- 账户详情去掉「已计入 / 未计入投资组合」。
- Portfolio 页：
  - 去掉「整户纳入」说明。
  - 列表按持仓或按账户分组的持仓列出，银行黄金与券商股票同等出现。
  - 不再把券商现金算进页顶总额。
  - 空态：还没有任何持仓。

### 数据

- 本轮不迁移、不删除 `include_in_portfolio` 列。写入可继续带当前值或固定 `false`；读取路径忽略它。
- Catalog 里的 `includeInPortfolio` 建议值不再驱动 UI。

**验收：**

- 招商银行复合账户里的黄金出现在 Portfolio；该账户现金不出现。
- 券商账户现金不计入 Portfolio 总额；其股票计入。
- 创建/编辑账户看不到计入投资组合勾选。

## 12. 持仓索引表可按列排序

**问题：** 标的页「所有持仓索引」表头不能排序。

**目标：** 每一列都可排序。

**方案：**

- 可点列：标的、账户、数量、成本、当前价值、未实现盈亏。
- 第一次点击升序，再点降序；表头有方向指示。
- 默认：当前价值降序；没有市值的行排在有市值的后面（或按标的名升序，实现时选一种并在表头体现）。
- 已有 `@tanstack/react-table`，用它做排序，不要自写一套不稳定比较。金额按数值比，不要按格式化字符串。
- 只影响这一张索引表。账户详情里的持仓表本轮不做，除非顺手复用同一 table 组件。

**验收：** 点击「当前价值」能按金额排序；再点反向。标的名可按本地化文字排序。

## 13. 转账：同币种锁定转入；不同币种按换汇

**问题：** 同币种转入本应等于转出，但自动同步同样只认第一位数字；两边都能改。不同币种没有汇率和计算。没有费用。

**目标：** 同币种只填转出。不同币种像换汇。都可以加可选费用。

**方案：**

选好转出/转入账户后，比较账户币种（简单账户用 `defaultCurrency`；复合账户用该笔现金币种，若当前表单仍是单币种转账则用账户默认币种）。

**同币种**

- 只显示转出金额，可编辑。
- 转入只读，始终等于转出（展示同一金额和币种）。不要第二套可编辑 Money 字段，也就没有同步 bug。
- 可选费用，默认空。费用币种锁定为转出币种。提交时从转出账户扣「转出+费用」（若后端今天不支持转账费用，本项与 Record 命令一起加可选 `fee`；没有费用则行为与现在相同）。
- 不需要计算按钮。

**不同币种**

- 转出、转入金额都可编辑，允许一侧空或 0。币种锁定为两端账户币种。
- 展示该币对汇率 `QuoteHint`（可更新）。估值所需币对按第 4/9 条默认提供方。
- **计算**与第 6 条相同：只填空侧；两侧都有正数则不覆盖。
- 可选费用，币种锁定为转出币种。
- 提交要求两侧都有正数。

**验收：** 同币种输入 320 时转入显示 320 且无法改。不同币种可只填转出再点计算得到转入。同币种连续输入多位数字，转入始终跟上。

## 15. 历史详情

**问题：** 只有一句摘要和修正/撤销，看不到完整字段。

**目标：** 每条有详情，打开后看到这条活动的全部用户可见信息。

**方案：**

- 列表每条增加「详情」（修正/撤销旁边）。
- 打开 Sheet，只读，包括：
  - 类型、当地日期时间、时区
  - 自然语言摘要（与列表同一套句子）
  - 买卖：账户、标的、方向、数量、单价、总额、费用
  - 转账：转出/转入账户与金额、费用（若有）
  - 换汇：卖出、买入、汇率、费用
  - 价值更新：账户、新值、差额方向、原因
  - 其他类型：各 effect 的账户/持仓、方向、金额或数量
  - 备注
  - 若为撤销或已被修正：相应标记
- 详情依赖完整 effects + TradeDetail（第 8 条）。可与「修正」共用一次加载，详情只读。

**验收：** 一笔买入的详情能看到账户、标的、数量、总额、费用，而不必去点修正。

## 16. 净资产趋势

**问题：** 趋势 = 已存每日快照 + 今天实时点。日常使用不会自动建快照，所以常常只有今天一个点。

**目标：** 历史已开始且过了至少一个已收盘日时，趋势是一条线，不是单点。今天仍用实时净资产。

**方案：**

- 分析页加载时（History 已开始）：若 `dirty_from` 有值或缺少 Origin 日到昨天的快照，则重建该闭区间。已有 `RebuildHistoricalSnapshots` / `DailySnapshotState`，差的是产品路径没有调用。
- 记录/修正/撤销之后，现有脏日期逻辑应触发从该当地日起重建；若现在只标脏不重建，分析页打开时补建即可。
- 图：
  - 没有已收盘日（今天才开始历史）：空态说明「从下一个已收盘日开始显示趋势」，不要只画一个今天的点冒充趋势。
  - 有快照：历史点 + 今天实时点。今天与最后快照同日时不要重复点。
- 重建失败要在分析页显示错误和重试，不要静默只剩一个点。

**验收：** 起始日为昨天或更早、有账户价值时，30 日/全部应有多个日期点。仅今天开始历史时是明确空态，不是单点折线。

## 共享交互：金额「计算」按钮

第 6、7、13 条共用同一套规则，实现时做成同一小组件，不要三个副本。

```text
[金额 A]     [金额 B]
当前汇率/价格 · 更新时间          [计算]
```

| 状态 | 计算 |
| --- | --- |
| 仅 A 有正数 | 用行情填 B |
| 仅 B 有正数 | 用行情填 A |
| 都有正数 | 不改 |
| 都空/0 | 提示，不改 |
| 没有行情 | 提示更新，不改 |

- 用现有 canonical 小数函数，不用 JS `Number`。
- 计算只改表单默认值；Preview/Record 仍走后端。
- 同币种转账不使用该按钮（转入只读镜像）。
