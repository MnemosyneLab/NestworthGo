## Scope and verification interpretation

The pre-fix reproduction assertions were changed to require correct behavior and
failed before implementation. Passing regression tests now assert the fixed
behavior; they are not the earlier characterization tests that passed on bugs.
Record/Fix each cover stale input and confirmation locking. Close/reopen and
cross-session response ordering are specifically tested on Record, not every
possible combination of Fix interactions.

For NW-007, `TestGainSnapshotQueryCountDoesNotGrowWithHoldings` measured 18 SQL
queries at both 4 and 504 holdings. `TestGainSnapshotRepresentative500Positions`
uses 500 positive positions with history costs and measured approximately 19 ms
for HoldingGain, 37 ms for AccountGains and 46 ms for InstrumentHoldings in one run.
These are representative synthetic measurements, not guarantees for arbitrary
history sizes. The snapshot intentionally materializes household inputs so
transfer recursion cannot read a different version. It does not hold a global
write lock or keep a transaction open while performing financial calculations.

NW-006's public contract and explicit request budget are documented in
[continuous-backup.md](development/continuous-backup.md#recovery-discovery-pages).
There is no silent limit of 100 points per stream or 512 streams. Only loaded
points are displayed; traversing additional storage pages requires an explicit
user action. The filesystem backend remains a local integration-test adapter.

Schema 15 only, no legacy migration, single-machine backup rather than dual-write
sync, and exclusion of the separate R2 credential SQLite database are intentional
product constraints. Native macOS GUI/signing, real R2/service behavior and real
ledgers were not validated in this environment. The coordinator records final
whole-repository gates and draft-PR validation separately.
