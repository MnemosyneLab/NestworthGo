# v0.3.4 Release Contract

## Status and ownership

Release closeout for `v0.3.4` / build `5`, approved for publication on
2026-09-20. Validation was performed against `d2c1a25` plus the local
release-documentation closeout. The release owner authorized publication
with the outstanding gates below explicitly recorded. Version metadata
is `0.3.4`; SQLite schema remains `11`. No database migration is
introduced by this change.

## Included scope

- Combined Portfolio page with Overview and Holdings tabs.
- Cross-account holdings grouped by instrument, expandable account rows,
  an account-detail view, native-currency cost/value/gain totals, and an
  optional zero-position filter. Missing FX does not hide valid native
  amounts. Holdings creation accepts an explicit unit cost after history
  starts so positions without a saved current price can still be recorded.
- Settings reorganized into appearance/language, market connections,
  backup/data, diagnostics, About, and reset, with section navigation and
  a shared preference save bar. Worker URL and token appear together;
  credentials retain independent save actions.
- Asset Changes opens on daily Asset Trend. Trend and Change Drivers share
  backend-calculated beginning/ending values, amount change, and percentage
  change, with explicit unavailable reasons. Percentage change includes cash
  flows and is not investment return. Insights controls and date shortcuts
  are simpler; resetting filters retains the active tab.
- FX conversion spread is separated from holding-period FX changes in Asset
  Changes and Return Analysis, with consistent trend totals and cash/account
  breakdowns.
- Versioned JSON export for external apps and scripts, including archived
  entities, full business and market history, and a current
  balance/holding/cost summary with explicit missing-value states. CSV
  import/export and mapping are removed; backup and restore remain the
  recovery path.
- Wails v3 desktop shell and `@wailsio/runtime` at `v3.0.0-beta.23`.
- Existing market-data, metals/crypto, repair, backup/restore, and schema
  `11` capabilities carry forward from [v0.3.3](v0.3.3.md).

## Upgrade and recovery

Preserve the existing backup and a closed copy of the database before
upgrade. Schema `9` upgrades through `10` to `11`; schema `10` upgrades to
`11` offline. Existing custom metals keep their original units and provider
semantics. Schemas `8` and earlier are unsupported; opening does not
silently recreate them.

The restore flow requires the current schema. A schema-9/10 backup archive
cannot be directly restored through the schema-11 restore flow. Keep the
older application and original files for rollback; after a successful
database upgrade, create and verify a new `.nestworth-backup`. Do not open
a migrated schema-11 database with v0.3.3 or earlier. JSON export is not a
full backup substitute.

## Reproducible local validation

Run from the repository root, sequentially: Vite rebuilds replace assets
embedded by Go, so do not run Go race tests during a frontend rebuild.

```bash
export SDKROOT="$(xcrun --sdk macosx --show-sdk-path)"
export GOCACHE=/tmp/nestworth-review-gocache
wails3 task check
go test -race ./...
(cd worker && npm test && npm run typecheck)
wails3 task package:release
codesign --verify --deep --strict dist/macos/Nestworth.app
```

Metadata must agree across `internal/version`, frontend package, Wails
configuration, macOS plists/Taskfile, Windows and Linux package metadata.
Expected bundle: `com.nestworth.app`, version `0.3.4`, build `5`, arm64.

## Native acceptance checklist

Use isolated `NESTWORTH_DATABASE_PATH` and `NESTWORTH_SETTINGS_PATH` values or
explicitly prepared test copies, and record results against the final package.

- [ ] Launch the packaged app, confirm About version/build, onboarding, relaunch,
      and persisted settings.
- [ ] Confirm Portfolio Overview/Holdings tabs, grouped holdings, zero-position
      filtering, and creating a position with explicit unit cost.
- [ ] Confirm Settings section navigation, preference save bar, and independent
      credential save actions.
- [ ] Confirm Asset Changes daily trend, shared period values, and FX conversion
      spread versus holding-period FX changes.
- [ ] Create and restore a schema-11 backup, then verify JSON export for a
      disposable household. Do not use CSV import/export.
- [ ] Verify Yahoo/Worker/CoinGecko/FX with configured test credentials, including
      missing keys, offline behavior, rate limits, and partial history.
- [ ] Review keyboard navigation, focus, English/Simplified/Traditional Chinese,
      window resizing, and performance on the intended hardware.
- [ ] Validate the minimum supported macOS version separately from the build host.

## Distribution handoff

Local artifacts belong under `dist/macos/`: `Nestworth.app`,
`Nestworth-0.3.4-arm64.dmg`, `Nestworth-0.3.4-arm64.zip`, and `SHA256SUMS`.
The local task ad-hoc signs the application; Developer ID signing and
notarization remain **NOT RUN**. Changing the signature requires recreating
both archives and checksums before publication.

The release owner authorized GitHub publication on 2026-09-20 with the local
ad-hoc signature and the unexecuted native/provider/Developer ID/notarization
gates recorded above. The release process commits this closeout, builds from
the clean revision, verifies the archives, and publishes the matching tag and
assets. Publication status and downloads are available on the
