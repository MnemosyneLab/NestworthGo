# Nestworth v0.3.10 (Build 11)

Release notes prepared for the next Apple Silicon macOS release. Publication and
acceptance evidence will be attached to the GitHub release after validation.

## Reconciliation and account workflows

- Keep unfinished reconciliation work first with collapsible account/item groups,
  exact ledger context, focused previews and safer refusal/retry recovery.
- Confirm an entire account after explicitly reviewing completeness. New activity
  reopens affected checkpoints while unrelated confirmations retain their evidence.
- Leave statement/source references blank when no reference is available. New
  cutoff dates follow today's civil date in the ledger timezone; saved and manually
  selected dates remain unchanged.
- Supplement transactions retain the primary account and exact holding identity,
  with counterparty and direction shown for two-sided operations.
- Filter account selection by owner, type and institution, apply filtered bulk
  actions, and preserve selections hidden by a filter.

## Investments, reviews and financial presentation

- Inspect each account's quantity, cost, value and unrealized gain for an instrument,
  including single-account and zero-position holdings.
- View simple annualized historical price/NAV returns for eligible bank investment
  products, mutual funds and ETFs. These describe instrument performance, not
  personal holding returns or guaranteed product yields.
- Review AND/OR condition trees, periods, comparisons, observations and match
  states using the version that produced the evidence. P0/P1/P2 priorities make
  the most urgent reviews easier to find.
- Liability balances display as negative; institution summaries and sorting use
  signed net values and preserve unavailable results. Credit-card inputs and
  stored magnitudes retain their existing financial semantics.
- Correct ordinary-reversal attribution and inverse trades, and keep property
  outside investment-cash classification. Shared controls improve holdings,
  account and overview consistency.

## MCP compatibility

MCP reads now use bounded compact `mcp-read/1` pages by default. This is a breaking
contract update: `responseMode`, legacy full-response paths and Agent offset
reads are removed. Growing evidence is traversed through the supplied cursors
and capture/detail references. Update integrations and install portable skill
**2.0.0** alongside the app. Financial write previews, commits, receipts and
idempotency boundaries are preserved.

## Upgrade compatibility

- Requires **macOS 27.0 or newer on Apple Silicon (arm64)**.
- New databases use **schema23**. Only verified schemas **21, 22 and 23** are
  supported. Verified schema21 upgrades to 22, then 23; verified schema22 upgrades
  to 23. Each step retains a verified, flushed, read-only recovery copy before
  mutation.
- v0.3.8's schema16 and other older, unversioned, invalid or future databases
  remain unsupported. Preserve original databases and verified backups; do not
  manually change a schema version. There is no general migration chain.
- Uses Wails **3.0.0** and Go **1.27.3**. No whole-app or Mac startup performance
  improvement is claimed.
