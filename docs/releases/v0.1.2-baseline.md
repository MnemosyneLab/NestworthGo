# v0.1.2 Baseline

This file records the evidence and locked decisions used before feature
implementation. It is intentionally based on sanitized fixtures and the
repository checkout, not on a real user's database.

## Current facts

- Application version: `v0.1.1` (`internal/version/version.go`).
- SQLite schema: `2` (`internal/infrastructure/sqlite/database.go`).
- Application boundary: Go domain and application packages behind a
  repository port; Fyne is owned by `internal/ui`.
- Exact financial decimal dependency: `shopspring/decimal`.
- Baseline gates: `go test ./...`, `go vet ./...`, and `git diff --check`.

## Locked v0.1.2 decisions

- Schema migration is ordered `2 -> 3`; future schema `4` is rejected before
  migration or business/settings writes.
- Quotes are append-only and selected by explicit source preference, then
  `quoted_at DESC`, `created_at DESC`, and `id DESC`.
- FX is stored as `1 base_currency = rate quote_currency`; valuation supports
  only direct or inverse conversion against the Household base currency.
- Missing inputs remain visible and make aggregates incomplete; they are never
  zero-filled.
- Provider identity is `yahoo_finance`; refresh is user-triggered only.
- Provider transport uses standard `net/http`, the fixed Yahoo host, an
  eight-second timeout, disabled redirects, a 2 MiB response cap, a shared
  two-request semaphore, an injectable fake transport, and the Rust client's
  non-compression browser header profile. It requests `Accept-Encoding:
  identity` and rejects an unexpectedly encoded response.

## Baseline command evidence

The clean pre-feature checkout passed:

```text
go test ./...
go vet ./...
git diff --check
```

The only test output warning was the platform linker warning about duplicate
`-lobjc` libraries while linking the Fyne test binary; it did not affect the
exit status.

## Fixtures

- `testdata/v0.1.2/schema2-v0.1.1.sql` is a sanitized schema-2 database seed
  containing active and archived references, Accounts, Ownership, values, and
  the retained relationships needed by migration tests.
- `testdata/v0.1.2/schema2-overview.json` records its exact pre-migration
  Overview result.
- `testdata/v0.1.2/portfolio-golden.json` contains the `62190 CNY` complete
  scenario and the `40990 CNY` partial scenario.
- `testdata/v0.1.2/yahoo/` contains sanitized chart envelopes for regular-price,
  close-fallback, FX, malformed and misaligned data, currency mismatch, API
  errors, and HTTP status cases. The oversized-body case is represented by a
  deterministic repeatable payload descriptor so the test can generate more
  than 2 MiB without storing a bulky artifact in the repository.

No fixture contains credentials, local paths, raw production logs, or a symbol
copied from a user's portfolio.
