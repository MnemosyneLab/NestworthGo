## Included scope

- Local household/account/holding management, History, Return Analysis,
  Asset Changes, backup/restore, and Accounts/Holdings CSV portability.
- Yahoo search and go-yfinance adapter, optional authenticated Cloudflare
  Worker routing, Tiingo history, and Frankfurter FX.
- CoinGecko crypto search using exact coin IDs, batched latest prices, daily
  UTC references, and local Demo-key settings. Existing bindings stay intact.
- Gold/silver templates using Yahoo futures references, grams or troy ounces,
  backend currency conversion, provenance, and CSV unit metadata. These are
  reference estimates, not physical-metal transaction or settlement prices.
- Instrument history based on first effective ownership, bounded by History
  Origin, with a seven-day lead-in and creation-date fallback when never held.
  CoinGecko history outside the adapter's Demo window remains an explicit gap.
- Repair previews with target names, date ranges, reuse decisions, current
  queries, and completed outcomes. Normal repair reuses fresh successful
  checks after restart; force refresh/recheck remains explicit.
- Backdated valuation and analytics repairs, inferred internal equity-market
  closures, quote observation metadata, Asset Changes contribution rows,
  manual FX side-panel entry, and configurable local diagnostic logging.

## Upgrade and recovery

Preserve the existing backup and a closed copy of the database before upgrade.
Schema `9` upgrades through `10` to `11`; schema `10` upgrades to `11` offline.
Existing custom metals keep their original units and provider semantics.
Schemas `8` and earlier are unsupported; opening does not silently recreate them.

The restore flow requires the current schema. A schema-9/10 backup archive
cannot be directly restored through the schema-11 restore flow. Keep the
older application and original files for rollback; after a successful database
upgrade, create and verify a new `.nestworth-backup`. Do not open a migrated
schema-11 database with v0.3.2. CSV is not a full backup substitute.

## Reproducible local validation

Run from the repository root, sequentially: Vite rebuilds replace assets
embedded by Go, so do not run Go race tests during a frontend rebuild.

```bash
export SDKROOT="$(xcrun --sdk macosx --show-sdk-path)"
export GOCACHE=/tmp/nestworth-review-gocache
wails3 task check
go test -race ./...
(cd worker && npm test && npm run typecheck)
wails3 task package:release
codesign --verify --deep --strict dist/macos/Nestworth.app
```

Metadata must agree across `internal/version`, frontend package, Wails
configuration, macOS plists/Taskfile, Windows and Linux package metadata.
Expected bundle: `com.nestworth.app`, version `0.3.3`, build `4`, arm64.

explicitly prepared test copies, and record results against the final package.

- [ ] Launch the packaged app, confirm About version/build, onboarding, relaunch,

`Nestworth-0.3.3-arm64.dmg`, `Nestworth-0.3.3-arm64.zip`, and `SHA256SUMS`.

notarization remain **NOT RUN**. Changing the signature requires recreating
both archives and checksums before publication.
