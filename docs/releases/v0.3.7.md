## Released scope

### MCP financial context and comparisons

Read-only `get_financial_context` captures a consistent single-state summary
with explicit disclosure behavior and frozen, paged details; the skill can
drill into a package item without re-reading household directories. The
two-state `compare_financial_context` reports right minus left and is not a
return or attribution calculation. `compare_financial_attribution` captures a
coherent comparison with an explicit compatibility link to change attribution.
Missing evidence remains unknown; summaries and captured detail have bounded
lifetimes and package-local references.

### Managed deposits, locked products and liquidity

MCP reads expose managed product contracts, product details, paginated
operation history, and household liquidity. Responses preserve original
currencies, missing values, actual versus forecast facts, routes/fees, settlement
assumptions and reservations. A forecast or `due_unconfirmed` state does not
prove cash receipt. Ordinary NAV-priced holdings remain on the usual
instrument/holding workflow unless represented as App-managed contracts.

Dedicated `ledger_write` preview/commit pairs record completed lifecycle facts
(open, record existing, receive interest, whole-contract settlement, and latest
safe undo), complete revisioned terms/policy edits, and actual value observations
for open locked products. Preview review, revisions, expiry and recoverable
operation receipts guard writes. These tools do not place bank or brokerage
orders. Renewal and reservation creation/edit/release remain App workflows;
generic trades, corrections or quote imports must not bypass managed-product
guards. Managed historical fix is not supported.

### Historical snapshots and UI/CI

Legacy period analysis and net-worth/portfolio trends now check the actual rows
needed for the requested date range instead of inferring continuous coverage
from a later completion watermark. Missing/stale coverage is rebuilt in bounded
31-day chunks, remains resumable after conflicts, and is diagnosed in health
repair. Financial valuation policy, schema and public application API do not
change. The regression record uses disposable synthetic ledgers and describes
coverage, concurrency and mixed-generation cases in
[`qa-legacy-snapshot-coverage-2026-10-08.md`](../testing/qa-legacy-snapshot-coverage-2026-10-08.md).

Other changes include millisecond precision consistency in holding creation
and 16px table-column spacing with horizontal scrolling at narrow widths for
managed-product rows.

Race CI now runs bounded application and MCP shards with `-race`, retains every
test and Go's default per-package timeout, and fails closed when the race-build
test selector cannot enumerate runnable tests. PR #45 at candidate main head
passed all shards and the ordinary test job. PR #47 (`df5d5b5`) then bounded
native dependency installation time; it merged at `57be6c1` on 2026-10-08
16:38 UTC. Its PR-head CI run 37807183123 passed the ordinary test job and all
race shards/gate. This changes scheduling and setup bounds, not the test
inventory or financial behavior. No CI polling was performed for this docs
update.

## User guidance and compatibility

The [Nestworth user skill guide](../user/nestworth-skill.md) documents install,
upgrade, connection and recovery. The skill is independently versioned at 1.6.0
and is supplied as a standalone archive plus adjacent SHA-256 file by the
release packaging task. Installing it neither updates the App/MCP server nor
connects a client or grants permissions. App MCP listens on local loopback;
client and App must be able to reach one another on the same machine.

Managed products retain their original contract terms, dates, currencies and
actual operation history. Forecast interest is not posted income or net worth;
unknown availability/value/FX is not zero. Do not infer cost basis from
principal/current value. The existing schema compatibility policy remains in
force: schema 15 is the only accepted database schema on this line, with no
automatic migration from schema 11 (v0.3.4) or other old/unversioned/future
schemas. Preserve old databases and backups; JSON export is not a restorable
backup. See the existing backup/recovery guidance before changing data.
