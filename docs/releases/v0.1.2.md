# v0.1.2 Release Contract

## Purpose and Status

**Release theme:** Know what everything is worth.

**Status:** `Phases 0–9 implemented; release closeout in progress`.

v0.1.2 extends the Go + Fyne v0.1.1 Household balance sheet into a
multi-currency current portfolio. It adds Instruments, Holdings, investment
cash, manual quotes, user-initiated Yahoo Finance current-price refresh, and
selectable FX refresh through Yahoo Finance or Frankfurter. It does not copy
the former Rust/Tauri implementation or treat the historical documents as
implementation evidence.

This document owns product scope and acceptance. The
[technical design](v0.1.2-technical-design.md) owns Go package, persistence,
valuation, provider, and Fyne contracts. The
[implementation plan](v0.1.2-implementation-plan.md) owns delivery order.

## Release Goal

A Household can retain each amount in its native currency and obtain an
authoritative current value in the immutable Household base currency. A user
can understand the local quote evidence behind each value, choose the provider
used for explicit FX refresh, and can complete the same workflow manually when
the selected provider is unavailable.

The central invariants are:

> Valuation reads only validated quotes already persisted in SQLite. It never
> performs a network request.

> Provider data is replaceable, untrusted input. Yahoo URLs, response fields,
> symbol rules, and JSON numbers stop at the infrastructure adapter.

> Missing inputs make results explicitly incomplete. They never become zero,
> one, an estimate, or a fabricated cross rate.

## Baseline

v0.1.2 starts from the current Go v0.1.1 implementation:

- SQLite schema version is `2`; a fresh database is created from schema `1`
  and migrated to `2` for the existing icon columns.
- `internal/domain` owns typed IDs, exact decimal `Money`, Category,
  TrackingMode, Ownership, Accounts, and Account Values.
- `internal/application.Service` owns use cases and Overview calculation behind
  a repository port.
- `internal/infrastructure/sqlite` owns migrations, transactions, snapshots,
  integrity checks, and the pre-migration `VACUUM INTO` copy.
- `internal/ui` is a live Fyne controller; there is no Tauri IPC, generated
  TypeScript binding, frontend HTTP capability, or browser cache.
- `holdings` is a parsed TrackingMode but Account creation intentionally rejects
  it as planned v0.1.2 behavior.

Every v0.1.1 identity, Account Value, archive state, Ownership row, filter, and
Overview result must remain valid after migration.

## User Stories

- As a Household member, I can create a Balance or Manual Value Account whose
  native currency differs from the Household base currency.
- As an investor, I can create a Holdings-tracked Investment Account without a
  fake initial Account Value.
- As an investor, I can create or reuse an Instrument and record its current
  non-negative quantity in an Account.
- As an investor, I can maintain multiple non-negative cash balances by currency
  inside one Holdings Account.
- As a user, I can enter manual Instrument prices and FX rates and explicitly
  choose Manual as the selected source.
- As a user, I can bind a supported Instrument to a Yahoo symbol, explicitly
  choose Provider, and refresh its current price.
- As a user, I can explicitly refresh required Provider-selected FX pairs.
- As a user, I can choose Yahoo Finance or Frankfurter in Settings for explicit
  FX refreshes without changing Instrument provider bindings.
- As a user, I can see native value, base value, quote source, quote time,
  freshness, and every missing input.
- As an offline user, I can open, browse, edit, and value all complete manual
  data without any provider request.

## Included

### Multi-Currency Accounts

- Keep the Household base currency immutable.
- Allow any syntactically valid three-letter uppercase Account currency.
- Convert Balance and Manual Value Accounts through a selected direct or inverse
  FX quote against the Household base currency.
- Retain and display native and base-currency values.

### Portfolio Model

- Household-scoped Instruments with type, quote currency, optional market and
  country metadata, optional Yahoo symbol, and Manual/Provider preference.
- Holdings-tracked Investment Accounts with current quantities.
- Append-only cash observations for multiple currencies in one Holdings Account.
- Archive and restore for Instruments and Holdings, preserving retained
  references.

### Quotes and Valuation

- Append-only manual and provider Instrument Quotes and FX Quotes.
- Household-scoped source preference for each normalized unordered FX pair.
- Deterministic source selection and deterministic latest-observation ordering.
- Direct or inverse FX only when one side is the Household base currency.
- One Go `ValuationService` used by Overview, Accounts, and Investments.
- Checked `shopspring/decimal` arithmetic at full precision; four-place
  midpoint-nearest-even rounding only at `Money` view-model boundaries.
- Manual, Fresh, Delayed, Stale, and Unavailable quote presentation.
- Per-component missing-input diagnostics and aggregate completeness.

### Current Yahoo Refresh

- One bundled, replaceable `yahoo_finance` adapter using Yahoo's chart endpoint.
- Current Instrument price from `regularMarketPrice`, falling back to the latest
  valid aligned daily close.
- Current direct FX from `{FROM}{TO}=X`.
- Yahoo requests use the same non-compression browser header profile as the
  Rust REST client. Go explicitly requests `Accept-Encoding: identity` so the
  response stays uncompressed without adding Brotli or Zstandard decoders.
- Explicit single-target and bulk refresh actions.
- At most two Yahoo requests in flight, an eight-second request timeout, a 2 MiB
  response cap, no redirects, no hidden retry, and operation-local 429 stop.
- Deterministic fake transports and sanitized fixtures in the default test gate;
  live Yahoo is never a default or release-proof test.

### FX Provider Routing

- Production registers `yahoo_finance` and the FX-only `frankfurter` provider.
- Settings persists the selected FX provider and defaults existing installations
  to Yahoo Finance. The choice affects only explicit FX refresh actions.
- Frankfurter uses its fixed public v2 latest-rate endpoint, requires no API
  key, preserves the returned decimal rate and date, and marks daily rates as
  delayed observations. See the [Frankfurter API](https://frankfurter.dev/).
- Only providers advertising `latestFX` appear in Settings. Instrument refresh
  continues to resolve the Instrument's saved provider key and symbol.

### Fyne Product Experience

- Holdings Account creation and detail editing.
- Instrument management, manual price entry, Yahoo binding, and current refresh.
- Required-FX management, manual entry, source choice, and current refresh.
- Settings-based FX provider selection with Yahoo Finance and Frankfurter
  attribution and availability notices.
- Investments page with valued subtotal, completeness, positions, Account
  totals, and allocation by currency, country, and Instrument type.
- English and Simplified Chinese loading, empty, partial, stale, unavailable,
  provider-error, and pending states.
- A visible bilingual disclaimer on every Yahoo-facing surface that Yahoo is an
  unofficial, unaffiliated source that may change or become unavailable.
- The selected Frankfurter FX surface states that it is an independent,
  unaffiliated daily-rate source that may change or become unavailable.

## Excluded

v0.1.2 does not implement:

- Activity, Buy, Sell, Transfer, Deposit, Withdrawal, Dividend, Interest, Fee,
  or automatic quantity changes
- Quantity history, cost basis, lots, gain, income, fees, TWR, XIRR,
  attribution, or benchmarks
- Historical portfolio charts, daily snapshots, provider daily-history
  backfill, or coverage cache
- Multi-hop FX, inferred cross rates, automatic symbol guessing, symbol search,
  ISIN resolution, or automatic currency changes from provider data
- Negative quantity, short positions, negative cash, margin, options,
  derivatives, or leverage
- Background, scheduled, startup, focus-triggered, or closed-application refresh
- Broker, bank, wallet, exchange, or custody synchronization
- API keys, OAuth, Keychain storage, custom endpoints, or arbitrary user-defined
  provider integrations
- Backup, restore, import, export, cloud sync, permanent deletion, changing the
  Household base currency, or converting an Account between TrackingModes

The Investments page reports current value, not return. A quantity edit is
current state and must not be presented as a trade.

## Locked Product Decisions

| Decision | v0.1.2 contract |
| --- | --- |
| Household base currency | Immutable after onboarding |
| Existing Accounts | Preserve mode, currency, Account Value history, and current results without reinterpretation |
| Holdings Account | Investment only; `initialAmount` is absent and no Account Value is written |
| TrackingMode/default currency | Immutable after Account creation |
| Financial authority | Go `ValuationService`; Fyne renders returned view models |
| Missing quote | Exclude only the affected component, keep its parent visible, and mark every parent aggregate incomplete |
| Aggregate meaning | Totals are valued subtotals of available components; `complete=false` means they are not a definitive total |
| Portfolio denominator | Allocations use the same valued component subtotal as Portfolio; unavailable components have no percentage |
| Quote preference | Manual or Provider is explicit; no silent fallback to the other source |
| Quote ordering | `quoted_at DESC`, `created_at DESC`, `id DESC` |
| FX routing | Direct or inverse against Household base only; no multi-hop |
| Provider | Bundled Yahoo current-quote adapter plus FX-only Frankfurter adapter; no search, history, credentials, or live-availability promise |
| Refresh trigger | User action only; no read/startup/mount/focus/timer request |
| Provider failure | Preserve local data and last successful quotes; return per-target partial results |
| Decimal boundary | No binary floating point for financial values; round only returned Money values |

## Acceptance Scenarios

### Golden Portfolio

A CNY Household has one Holdings Account containing:

| Position | Native input |
| --- | --- |
| SGD cash | `5000 SGD` |
| QQQ | `3 × 700 USD` |
| ES3 | `1000 × 4 SGD` |

With `1 USD = 6.9 CNY` and `1 SGD = 5.3 CNY`, the service returns:

```text
SGD cash   = 26,500 CNY
QQQ        = 14,490 CNY
ES3        = 21,200 CNY
Account    = 62,190 CNY
```

Manual and Provider quotes with the same decimals produce identical values and
different provenance. Direct and inverse FX produce the same rounded result.

### Partial Valuation

If ES3 has no selected Instrument quote, SGD cash and QQQ still contribute
`40,990 CNY`. Account, Portfolio, and Overview report that valued subtotal with
`complete=false` and identify ES3's missing price. No surface shows ES3 as zero.

### Current Instrument Refresh

An active QQQ Instrument has `provider_key=yahoo_finance`,
`provider_symbol=QQQ`, quote currency USD, and Provider preference. Refresh
validates a single Yahoo chart result and appends a provider quote. It changes
neither quote currency nor preference. A repeated identical observation is a
`cached` no-op; a changed value at the same provider timestamp appends a newer
observation.

### Direct FX Refresh

Valuation requires USD/CNY and the normalized pair is Provider-selected.
Refresh requests `USDCNY=X`, validates the direct positive decimal and
timestamp, and appends a USD-to-CNY quote. Failure preserves the last valid
local quote and reports only that target as failed.

### Frankfurter FX Refresh

When Settings selects Frankfurter, the same USD/CNY target requests the fixed
`/v2/rate/USD/CNY` route, validates the returned base, quote, date, and positive
decimal rate, and stores the result as a delayed provider observation with
`source_key=frankfurter`. A provider error preserves the last valid local quote;
it never falls back silently to Yahoo or a manual quote.

### Offline and Rate Limit

Startup and ordinary reads issue zero HTTP requests. During bulk refresh, two
targets may commit before Yahoo returns 429; those commits remain, the failing
target reports `rate_limited`, later Yahoo targets report skipped due to rate
limit, and no automatic retry occurs.

## Release Acceptance

v0.1.2 is development-complete only when:

- A committed sanitized schema-2 v0.1.1 fixture migrates to schema `3`, retains
  every old row and relationship, and produces the same pre-feature Overview.
- Fresh creation, migration reopen, integrity checks, pre-migration snapshot,
  and future schema `4` zero-write/no-network behavior pass.
- Holdings creation writes no fake Account Value; Balance and Manual Value
  behavior remains unchanged except for supported FX conversion.
- Instrument, Holding, cash, quote, source-preference, archive, and restore
  invariants are enforced atomically.
- Exact decimal parsing, multiplication, inversion, aggregation, overflow, and
  rounding are covered without `float32` or `float64` financial conversion.
- Overview, Account detail, and Investments agree from one consistent SQLite
  read snapshot and expose identical missing-input diagnostics.
- Yahoo parsing, currency validation, fallback, response limits, status mapping,
  timeout, cancellation, concurrency, 429 stop, deduplication, and partial
  persistence pass against deterministic fixtures.
- Frankfurter parsing, decimal preservation, date/freshness semantics, response
  limits, status mapping, timeout, cancellation, redirect rejection, and
  partial persistence pass against deterministic fixtures.
- Startup, bootstrap, passive reads, route construction, and window focus make
  zero provider calls; Manual-selected targets are never sent to a provider.
- Provider-facing Fyne workflows are non-blocking, cancel when their owning
  view closes, prevent duplicate submit, and safely marshal completion back to
  the UI thread.
- English and Simplified Chinese key sets, keyboard operation, visible focus,
  status announcements, and provider disclaimers are verified.
- `go test ./...`, `go vet ./...`, `gofmt` drift, race-enabled service/provider
  tests, `git diff --check`, isolated-data launch, arm64 packaging, and the named
  macOS accessibility/signing checks are recorded.

## Compatibility Promises

v0.1.2 preserves every v0.1.1 promise and adds:

- Instrument, Holding, cash-observation, Instrument Quote, and FX Quote IDs are
  stable typed UUID identities.
- Quotes are append-only observations; refresh never rewrites quote history.
- Holding quantity is current state, not historical evidence of a trade.
- v0.1.3 must not fabricate past trades or cash flows from v0.1.2 current state.
- Native amount, native currency, base value, quote provenance, and completeness
  remain distinguishable.
- Provider keys and symbols are metadata, never Instrument identity.
- Stored normalized quotes remain usable if a provider changes or is removed.
- Complete manual valuation remains available without network access.
