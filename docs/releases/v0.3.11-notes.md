# Nestworth v0.3.11 (Build 12)

Prepared notes for the next Apple Silicon macOS release. **Unreleased.** Final
source, checksums, package verification and acceptance belong in the release
record after they have been performed.

## Desktop assistant and navigation

- Use an opt-in built-in desktop AI assistant with streaming replies, persistent
  conversations, conversation switching/naming and visible tool inputs/results.
- Select enabled models and supported reasoning efforts from an offline catalogue.
  Model access still depends on your API account. Voice input sends a recording
  to OpenAI for transcription and appends editable text; it never sends the draft
  automatically.
- Review local request usage, partial/unknown counts and versioned USD estimates.
  These estimates are not provider invoices; missing usage is not treated as zero.
- Read-only is the default. Explicit **Read & Write** enables the shared MCP
  business tools, including ledger preview/commit, without per-write approval.
  Restart, restore or configuration changes revoke this session permission.
- Navigate with Back, Forward and Recent; use scoped page reads and controls,
  clearer return paths and layouts that retain financial values in narrow windows.

The assistant requires explicit enablement and an OpenAI API key. AI credentials
are stored without field encryption in the household SQLite database and enter
full database backups. Conversations and usage live in private sidecars outside
those backups. New sidecar fields are not supported by older strict-decoding
binaries; downgrading against the updated sidecar is unsupported. See the
[runtime](../architecture/builtin-ai-runtime.md), [model selection](../architecture/ai-model-selection.md),
[voice](../architecture/ai-voice-input.md) and [usage](../architecture/ai-usage.md) contracts.

## Mobile access, reviews and financial correctness

- Enable mobile web access from the running desktop app using a private LAN
  address and token. Use daily recording, health and market workflows with
  revocable, optionally remembered browser sessions. Mobile model access is closed.
- Mobile HTTP sends credentials and financial data in plaintext: use a trusted
  device and LAN. It does not provide HTTPS, cloud hosting or multi-device sync.
  Legacy unversioned access settings reopen disabled; apply the new settings to
  configure access. See [mobile setup and migration](../design/mobile-web-access.md).
- Inspect return contributions and adjacent calendar periods, summarized review
  alerts and daily evidence. Account detail pages share consistent recording actions.
- Correct historical traded/backfilled holding attribution, quantity adjustments,
  transfer-cost conservation and unavailable cost handling; tighten undo and backup
  startup recovery. Mobile confirmation recovery after restart does not replay writes.
- Remove the Tiingo market-data source. Yahoo, CoinGecko, Frankfurter FX and
  manual/Agent observations remain. Saved Tiingo preferences are not converted to
  a different source automatically; select a supported source explicitly.

## Breaking MCP compatibility

MCP implementation **5.0.0** returns successful results in `structuredContent`
with an empty `content` array. Text-only clients must update. Errors retain text,
output-schema validation remains enabled and the complete-response limit remains
64 KiB. Read envelopes use `mcp-read/2`, shared continuations use `get_read_page`,
and plan commits use `commit_plan`; removed aliases are not supported. Consult
live `tools/list` and the [current MCP contract](../development/mcp.md) instead
of caching an old tool inventory. Install the independent portable skill
**3.0.21** separately. Historical single-day reads and targeted pending filters
avoid duplicate endpoints and unnecessary ordinary-row scans; this is not a
whole-app latency or model-token claim.

## Upgrade compatibility and acceptance

Requires **macOS 27.0+ on Apple Silicon (arm64)**, Go **1.27.3** and Wails/runtime
**3.1.0**. New databases use **schema23**. Only verified schemas **21, 22 and 23**
are supported; ordered 21→22→23 or 22→23 upgrades retain a verified, flushed,
read-only recovery copy before each mutation. v0.3.8's schema16 and other older,
unversioned, malformed or future databases remain unsupported. Preserve originals
and verified backups; do not manually edit schema versions.

Final native packages, signing/notarization, archive launch/relaunch, GUI,
accessibility, voice and real-provider/client acceptance are pending for this
candidate. Prior release waivers do not apply. Record only checks actually run
against the final selected source; see the [preparation record](v0.3.11.md).
