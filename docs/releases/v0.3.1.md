# v0.3.1 Release Contract

## Status

`0.3.1` is the current unreleased development line (build `2`). Public
publication is not implied by synchronized local metadata. The `0.3.0` line is
superseded and was never published.

## Release goal

Carry forward the Wails v3 local-first desktop, backup/restore, and create-only
Accounts/Holdings CSV workflows from `0.3.0`, and add the verified Go-only
Analytics Phase 1a kernel. The business SQLite schema remains `9`.

## Included capability

Everything in the `0.3.0` desktop surface, plus:

- Scoped Analysis and Investment universes with typed query contracts;
- one-pass value-effect classification and signed Asset Changes identity;
- path-aware holding and cash Price/FX formulas with residuals computed after
  classification and currency-aware tolerances;
- corporate-action and in-kind handling without synthetic prices;
- interest reason support for money-in and value-update paths;
- History Origin timezone assignment, including non-24-hour DST days;
- Phase 1a golden-case coverage for the Asset Changes kernel.

## Non-goals

This release does not include ReturnComponent, DietzCapitalFlow, rates,
geometric linking, Wails Analytics methods, React Analytics pages, memoized API
projections, or the remaining Analytics phases. Cloud backup, synchronization,
direct bank/broker integrations, background refresh, signing, notarization, and
public artifact publication also remain outside this contract.

## Technical invariants

- The frontend does not open SQLite, issue HTTP requests, or recalculate
  authoritative financial values.
- Financial values cross the Wails boundary as lossless decimal strings and
  typed wire DTOs.
- Beginning + signed AssetBucket drivers + residual equals ending for every
  supported scope; liabilities contribute with negative sign.
- Price and FX are path components, not leftovers; cash FX subtracts all
  recorded native movements at their event-time rates.
- Missing quotes or missing instruments produce an explicit incomplete result
  and are never silently replaced with zero.
- Posted financial changes remain immutable; corrections and reversals append
  linked facts.

## Acceptance checks

The Phase 1a automated closeout is:

```bash
GOCACHE=/tmp/nestworth-go-0.3.1 go test ./...
GOCACHE=/tmp/nestworth-go-0.3.1 go test -race ./...
GOCACHE=/tmp/nestworth-go-0.3.1 go vet ./...
gofmt -l cmd internal
go build ./cmd/nestworth
cd frontend && pnpm run lint && pnpm run typecheck && pnpm run test
git diff --check
```

The packaging smoke target is:

```bash
wails3 task darwin:package:release
```

The resulting local artifacts should identify as `0.3.1`, build `2`, bundle
ID `com.nestworth.app`, and arm64 on the primary target. Manual keyboard and
accessibility review, signing, notarization, and artifact retention must be
reported separately from automated checks.

## Completion rule

The release is ready for publication only when the included capability is
covered by code and relevant tests, all synchronized metadata reports `0.3.1`
and build `2`, the packaging smoke is independently inspected, and every
remaining manual gate is either completed or explicitly accepted by the
release owner.
