# v0.2.1 Release Contract

## Status

`0.2.1` is the current unreleased development line (build `2`). Public
publication is not implied by synchronized local metadata. The `0.2.0` line
is superseded and was never published.

## Release goal

Keep the Wails v3 local-first desktop, with Go as the sole financial
authority, and replace the Account category model with the frozen
account-container contract: `account_type`, `balance_sheet_role`, and
`tracking_mode` on schema `7`.

## Included capability

Everything in the `0.2.0` desktop surface, plus:

- Closed legal (type, role, tracking) combinations shared by create and update;
- Role and tracking immutable after create; type editable only when still legal
  with the frozen role and tracking;
- Whole-account `include_in_portfolio` (no `include_in_investment`);
- Overview `assetsByType` and `liabilitiesByType` at component granularity;
- Simple historical buckets marked `classificationBasis=current-metadata-derived`;
- Schema `7` create-or-open-only: empty files become v7; `user_version == 7`
  with a passing verifier starts; any other version is rejected and the file
  is left unchanged.

## Non-goals

This release does not include backup/restore, import/export,
synchronization, direct bank/broker/wallet integrations, background refresh,
tax reporting, budgeting, multi-user permissions, signing, notarization, or
public artifact publication. It also does not migrate schema `6` databases,
introduce SubAccount, convert tracking modes, or add component-level
inclusion.

## Technical invariants

- The frontend does not open SQLite, issue HTTP requests, or recalculate
  authoritative financial values.
- Financial values cross the Wails boundary as lossless decimal strings and
  typed wire DTOs.
- Multi-entity mutations are validated and committed atomically.
- Posted financial changes are immutable; corrections and reversals append
  linked facts.
- Missing quotes or missing instruments produce an explicit incomplete result
  and are never silently replaced with zero.
- Database compatibility and integrity are checked before business writes.
  Incompatible files, including schema `6`, must be replaced by creating a
  new database.

## Acceptance checks

The automated closeout is:

```bash
GOCACHE=/tmp/nestworth-go-0.2.1 go test ./...
GOCACHE=/tmp/nestworth-go-0.2.1 go test -race ./...
GOCACHE=/tmp/nestworth-go-0.2.1 go vet ./...
gofmt -l cmd internal
go build ./cmd/nestworth
cd frontend && pnpm run lint && pnpm run typecheck && pnpm run test
git diff --check
```

The packaging smoke target is:

```bash
wails3 task darwin:package:release
```

The resulting local artifacts should identify as `0.2.1`, build `2`, bundle
ID `com.nestworth.app`, and arm64 on the primary target. Manual keyboard and
accessibility review, signing, notarization, and artifact retention must be
reported separately from automated checks.

## Completion rule

The release is ready for publication only when the included capability is
covered by code and relevant tests, all synchronized metadata reports
`0.2.1`, the packaging smoke is independently inspected, and every remaining
manual gate is either completed or explicitly accepted by the release owner.
