## Implemented behavior

Settings supports opt-in continuous backup to R2, account/bucket configuration,
atomic credential-pair replacement/removal, connection testing, manual backup,
status and a last successful remote-confirmed backup timestamp. Backup only
runs while the app runs. Shared provider/R2 secret fields use fixed masks and
show only newly typed input; blank saves keep stored keys.

The schema-15 business database includes existing provider and AI/MCP settings.
Private plaintext R2 credentials, backup identity and status are separate in
`backup_config.db`, excluded from business backup/export/MCP. Each app start or
reconfiguration creates a fresh isolated stream. A small per-stream identity record verifies the app ID, source version/build
and schema before recovery. A local duplicate-instance lock fences the business path. There is no multi-device sync or cloud election.
Disable never deletes history. Optional 30/90-day whole-stream retention is off
by default, requires irreversible-deletion acknowledgment, and protects current,
unknown/unsealed/foreign streams plus the newest two sealed streams after actual
restore verification. Stale previews and changed ETags reject deletion. The
pinned S3 layout is `<stream>/0000/<minTXID>-<maxTXID>.ltx`; no compaction or
periodic stream rotation bounds storage for a long-running current stream.

Cloud recovery lists streams/points, downloads a separate candidate, verifies
all current schema requirements, previews it and requires acknowledgment plus
typed RESTORE. Installation shares existing write coordination, safety copies,
atomic file swap and startup journal rollback. After restore, backup remains
paused until restart and explicit re-enable into a new stream. Unsupported
schema 0/9–14/future, incomplete schema, empty/not-found and failed candidates
are rejected without installing them.

See [continuous-backup implementation notes](../development/continuous-backup.md)
for lifecycle details, storage growth, listing limits and R2 permissions.

## Mac packaging handoff

On the Mac, replace `REVIEWED_SHA` with the final reviewed, merged SHA:

```bash
git fetch origin --tags
git switch --detach REVIEWED_SHA
git status --short
git rev-parse HEAD
wails3 task check
GOCACHE=/tmp/nestworth-go-0.3.6 go test -race ./...
wails3 task package:release
wails3 task darwin:verify:package
(cd dist/macos && shasum -a 256 -c SHA256SUMS)
(cd dist/skills && shasum -a 256 -c nestworth-skill.tar.gz.sha256)
```

Require a clean checkout and retain source SHA and command results. Fresh outputs:
`dist/macos/Nestworth.app`, `Nestworth-0.3.6-arm64.dmg`,
`Nestworth-0.3.6-arm64.zip`, `SHA256SUMS` (all under `dist/macos`), plus
`dist/skills/nestworth-skill.tar.gz` and its `.sha256` file. Publish the two
archives, checksum manifest and skill archive/checksum after parent verification.
Follow the [isolated Mac acceptance guide](../development/local-workflow.md#release-artifacts-and-isolated-mac-acceptance)
for extracted ZIP/DMG smoke tests with temporary data/settings. Do not reuse
v0.3.5 binaries. If signing/notarizing, follow that guide's repackaging sequence:
the ordinary release task rebuilds and ad-hoc signs, so do not rerun it afterward.

Cancellation-safe cleanup joins every owned worker before closing SQLite;
initialization and its failure closes are drained as well. Initial setup may
briefly queue local SQL while the bounded initialization runs. A custom backend
that ignores context cancellation can delay shutdown until its operation
returns; it is never abandoned against a closed database. Production exposes
only the SDK-backed HTTPS R2 adapter, with TLS verification. This is a library
interface limitation, not an unconditional hard shutdown-deadline guarantee.
