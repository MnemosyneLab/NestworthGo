## Implemented behavior

Settings supports opt-in continuous backup to R2, account/bucket configuration,
atomic credential-pair replacement/removal, connection testing, manual backup,
status and a last successful remote-confirmed backup timestamp. Backup only
runs while the app runs. Shared provider/R2 secret fields use fixed masks and
show only newly typed input; blank saves keep stored keys.

The schema-15 business database includes existing provider and AI/MCP settings.
Private plaintext R2 credentials, backup identity and status are separate in
`backup_config.db`, excluded from business backup/export/MCP. Each app start or
reconfiguration creates a fresh isolated stream. A local duplicate-instance
lock fences the business path. There is no multi-device sync or cloud election.
Disable never deletes history; compaction/retention are off in this first version.

Cloud recovery lists streams/points, downloads a separate candidate, verifies
all current schema requirements, previews it and requires acknowledgment plus
typed RESTORE. Installation shares existing write coordination, safety copies,
atomic file swap and startup journal rollback. After restore, backup remains
paused until restart and explicit re-enable into a new stream. Unsupported
schema 0/9–14/future, incomplete schema, empty/not-found and failed candidates
are rejected without installing them.

See [continuous-backup implementation notes](../development/continuous-backup.md)
for lifecycle details, storage growth, listing limits and R2 permissions.

## Validation and remaining gates

Validation is performed against temporary local databases/file object stores,
never real household data or R2 credentials. Test coverage includes baseline
and incremental recovery, isolated restart, offline retry, cancellation,
initialization failure with queued app transactions, failed stop drains,
configuration swap, last-attempt/success distinction, confirmation/cancel,
safety retention, journal rollback and schema-15-only acceptance. Frontend
coverage exercises shared secrets, complete-pair save, failed-save input
retention, repeated operations and destructive restore confirmation.

Exact full-suite results and source-head CI evidence are recorded in the PR.
Required automated commands are:

```bash
go test ./...
go test -race ./...
go vet ./...
go build ./cmd/nestworth
pnpm --dir frontend run check:bindings
pnpm --dir frontend run typecheck
pnpm --dir frontend run lint
pnpm --dir frontend run test
pnpm --dir frontend run build
python3 tools/check-nestworth-skill.py
python3 -m unittest discover -s tools/tests -v
git diff --check
```

The saved Linux cloud environment lacks GTK/WebKit development packages and
cannot install them without privileged package access. Local Go app checks
use `CGO_ENABLED=0` with `GOFLAGS='-mod=readonly -tags=server'`; race checks cover
non-native packages with cgo. PR CI installs native dependencies and runs the
normal full Go/test/race/vet/build suite. These local substitutions do not
establish native Mac behavior.

Pending release-owner gates:

- Live R2 listing, write permission, baseline/incremental restore and offline
  reconnect using an isolated safe database and user-entered credentials.
- Native Mac UI acceptance of secret replacement/removal, enable/disable,
  restart, target changes, timestamps, preview cancellation, restore, safety
  copies and explicit re-enable.
- macOS package metadata/architecture, signing/notarization and artifact checks.
- Parent review of the final source head and exact-head passing CI before merge.

Cancellation-safe cleanup joins every owned worker before closing SQLite;
initialization and its failure closes are drained as well. Initial setup may
briefly queue local SQL while the bounded initialization runs. A custom backend
that ignores context cancellation can delay shutdown until its operation
returns; it is never abandoned against a closed database. Production exposes
only the SDK-backed HTTPS R2 adapter, with TLS verification. This is a library
interface limitation, not an unconditional hard shutdown-deadline guarantee.
