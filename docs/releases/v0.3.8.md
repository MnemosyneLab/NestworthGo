## Candidate scope

- Upcoming actions through D+30, a clearer home page, Historical Panorama comparisons and bounded trends, account composition/currency displays, investment short names, and saved-instrument selectors.
- Opt-in unit-NAV investment reviews, cash-balance adjustment previews, and eligible ordinary-activity Repeat drafts with confirmation/retry recovery.
- Local MCP reads for upcoming actions, investment reviews and History; permission-checked Available Funds withdrawal-policy plans; opt-in frozen management pages, separately paged reservations, bounded multi-target market reads, atomic metadata/review batches, version checks, and recoverable receipts.
- Reliability fixes for transfer basis/proceeds, same-time ordering, liability and same-currency previews, Record/Fix retry identity, delayed-NAV estimate display, bounded operation history/undo availability, historical coverage and cancellation, and safe backup metadata cleanup/restore fencing.
- Skill 1.9.0 remains separately installed. These scoped optimizations are not measured whole-app or startup speed claims.

See [candidate release notes](v0.3.8-notes.md) for user-facing detail and compatibility guidance.

## Exact Mac handoff

Use the authorized MacBook once it is online. The Mac mini is not authorized for this task. The handoff must use the exact approved release source and a clean checkout; do not assume this cloud workspace's files are present there.

1. Check clean status and exact source SHA; record `go version`, Node, pnpm, Wails, Xcode, and macOS versions. Use compatible Go 1.26.x, Node 22, pnpm 12.2.1, and Wails `v3.0.0-beta.28`. Keep the checkout on local non-synchronized storage and set `SDKROOT` from `xcrun --sdk macosx --show-sdk-path`.
2. Run remaining required native GUI/accessibility and synthetic schema 15→16 upgrade/rollback acceptance, then real local MCP-client and skill 1.9.0 acceptance using synthetic data. Record unrun or failed checks distinctly.
3. Run `wails3 task package:release`, then verify `dist/macos/SHA256SUMS` and the skill checksum. Confirm production ID `com.nestworth.app`, version 0.3.8, build 9, arm64, signature, and ZIP/DMG payload integrity.
4. Independently extract/copy each archive payload with metadata preservation. Launch and relaunch the DMG payload and ZIP payload separately using distinct fresh `NESTWORTH_DATABASE_PATH` and `NESTWORTH_SETTINGS_PATH`, create a synthetic household in each, and verify persistence after relaunch. Do not substitute the staging app launch.
5. Create the actual dated QA record with exact commands/results, native host/toolchain, both payload results, all five asset sizes/SHA-256 values, signing/runtime status, and remaining gates. Do not transmit signing credentials or bypass macOS security warnings.
6. Only after verified artifacts and required gates or explicit recorded waivers, freeze one approved source SHA, create an annotated `v0.3.8` tag at that SHA, stage the draft GitHub release with all five assets, independently download and reverify them, then publish. Confirm tag SHA, release flags, asset inventory, and remote digests before closeout.

The current repository has no release workflow, tag-triggered package job, or artifact producer. `wails3 task package:release` and Darwin verifier tasks are macOS-only and require native Xcode/SDK, CGO, `hdiutil`, `ditto`, `PlistBuddy`, `lipo`, and `codesign`. Cloud preparation cannot satisfy those gates.
