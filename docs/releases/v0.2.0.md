# v0.2.0 Release Contract

## Status

`0.2.0` is the current unreleased development line. The repository has one
desktop runtime, one canonical entry point, and one current documentation
system. Public publication is not implied by synchronized local metadata.

## Release goal

Deliver a coherent local-first desktop application around Wails v3, with the
Go domain/application layers as the sole financial authority and the React
frontend as the presentation and interaction layer.

## Included capability

- Household onboarding with base-currency and member setup;
- Accounts, Members, Institutions, Groups, Instruments, and Holdings;
- Exact decimal money and quantity handling with local SQLite persistence;
- Multi-currency valuation and explicit provider refresh for instrument quotes
  and FX rates;
- Immutable Activities, History Origin, replay, historical snapshots, and
  correction-oriented History workflows;
- Average-cost capture/replay, realized and unrealized gain, currency
  decomposition, and Analytics;
- Wails service bindings with typed DTOs, stable error codes, and localized
  frontend presentation;
- Settings persistence for appearance, language, display formats, window
  state, and FX provider routing.

## Non-goals

This release does not include backup/restore, import/export,
synchronization, direct bank/broker/wallet integrations, background refresh,
tax reporting, budgeting, multi-user permissions, signing, notarization, or
public artifact publication.

## Technical invariants

- The frontend does not open SQLite, issue HTTP requests, or recalculate
  authoritative financial values.
- Financial values cross the Wails boundary as lossless decimal strings and
  typed wire DTOs.
- Multi-entity mutations are validated and committed atomically.
- Posted financial changes are immutable; corrections and reversals append
  linked facts.
- Missing quotes produce an explicit incomplete/unavailable result and are
  never silently replaced with zero.
- Database compatibility and integrity are checked before business writes.

## Acceptance checks

The automated closeout is:

```bash
GOCACHE=/tmp/nestworth-go-0.2.0 go test ./...
GOCACHE=/tmp/nestworth-go-0.2.0 go test -race ./...
GOCACHE=/tmp/nestworth-go-0.2.0 go vet ./...
gofmt -l cmd internal
go build ./cmd/nestworth
cd frontend && pnpm run lint && pnpm run typecheck && pnpm run test
git diff --check
```

The packaging smoke target is:

```bash
wails3 task darwin:package:release
```

The resulting local artifacts should identify as `0.2.0`, build `1`, bundle
ID `com.nestworth.app`, and arm64 on the primary target. Manual keyboard and
accessibility review, signing, notarization, and artifact retention must be
reported separately from automated checks.

## Completion rule

The release is ready for publication only when the included capability is
covered by code and relevant tests, all synchronized metadata reports
`0.2.0`, the packaging smoke is independently inspected, and every remaining
manual gate is either completed or explicitly accepted by the release owner.
