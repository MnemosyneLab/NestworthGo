## Scope

### Household and analysis

- Household Overview shows net-worth history and account/member/institution/
  group breakdowns. Data Health links missing valuation and market-history
  inputs to their affected source and offers explicit repair previews.
- Portfolio and Holdings provide multi-currency positions and cash. Return
  Analysis, Asset Changes, contribution detail and History use backend-owned
  financial calculations and expose incomplete data rather than inventing
  totals.

### Available Funds and managed products

- Available Funds estimates access to existing household assets for Today,
  7-day, 30-day and custom future horizons. Source rules, reservations, current
  valuation/FX, fees and assumptions are visible. Results can be complete,
  partial or unavailable; the estimate is not a budget or safe-to-spend advice.
- Managed term deposits and locked products can be opened from tracked cash or
  recorded as already owned, valued, redeemed, settled, and renewed through
  explicit previews and atomic ledger operations.
- Future interest is an estimate until received. Due dates do not create cash
  or income automatically. Partial subscriptions/redemptions, variable-rate
  forecasts, compounding, taxes, holiday calendars, future wages/expenses and
  background product operations are outside this release.

### Local MCP and sourced data

- Settings can enable local loopback MCP in read-only, directory_write or
  ledger_write permission modes. Available tools include household/directory
  and portfolio reads, staged ledger writes, atomic batches, position imports
  and transfers, contribution queries, balance/quantity/cost reconciliation,
  historical corrections/reversals, and data-health repair jobs.
- Agent-supplied instrument and FX observations can be recorded with source
  evidence. This is a local input source; the App does not contact an Agent
  endpoint. Configured Yahoo, Tiingo and CoinGecko instrument sources and
  Frankfurter FX remain explicit refresh routes.
- MCP does not expose arbitrary SQL, filesystem access, backup/restore,
  credential-management, cloud relay, or brokerage order placement.

## Compatibility and data safety

Schema 15 is the only accepted schema for an existing database in this line.
A new database is created at schema 15. v0.3.4's schema-11 database, any older
or unversioned database, and a database from a future schema are rejected
nondestructively. The app probes an existing file read-only and does not
migrate, delete or recreate it. Current-schema backups must also pass
read-only verification before restore; older-schema backups are not upgraded.

Preserve the original database and its backups before changing application
versions. Do not delete or replace an incompatible database as a troubleshooting
step. The versioned JSON export is an external data copy and cannot restore the
household. CSV import/export has been removed. Core browsing and editing remain
local-first; cloud backup (including Litestream/R2), synchronization, direct
bank/brokerage links and background refresh are not part of this release.

## Package preparation

On a Mac, from the exact reviewed source commit, run:

    wails3 task check
    GOCACHE=/tmp/nestworth-go-0.3.5 go test -race ./...
    wails3 task package:release

The root package task runs the existing user-skill reference/installer tests,
builds the standalone skill bundle and checksum, then invokes the Darwin
packaging task. The Darwin task copies only the built app into the package
staging area, creates the versioned arm64 DMG and a ZIP with ditto resource,
extended-attribute and ACL metadata preserved, verifies the app/archives and
writes checksums for the DMG and ZIP. Expected outputs are listed above.
Generated files under dist are ignored and are not committed.

The app bundle is assembled from the current build executable, release
Info.plist, expected icon, optional `Assets.car`, and generated code-signature
metadata in a fresh staging directory; the task replaces only its
repository-local `bin/Nestworth.app` output. The ZIP contains that `.app`
bundle. The DMG contains the same app plus an `/Applications` shortcut and a
volume icon. The verifier compares the app executable, plist, icon and optional
`Assets.car` in both archives with the current app, and checks the expected
icon. The skill packager has an explicit file allowlist.

Do not add local databases, settings files, logs, credentials or user-profile
content to `dist`. See the [local workflow](../development/local-workflow.md)
for isolated launch, read-only DMG inspection, checksums, and cleanup steps.

The .app is ad-hoc signed for local launch. This does not establish Developer
ID signing, notarization, Gatekeeper acceptance, or distribution readiness.
Do not report a minimum macOS version as accepted based solely on the plist.
