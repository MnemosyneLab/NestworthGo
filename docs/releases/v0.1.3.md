# v0.1.3 Release Contract

## Purpose and Status

**Release theme:** Family Timeline and History — remember what changed.

**Status:** `Phases 0–10 implemented; unsigned public-release checks pending`.

v0.1.3 adds a simple Household change timeline and trustworthy net-worth
history on top of the v0.1.2 current portfolio. The user records what happened
in familiar language; Go constructs the internal immutable financial effects
and keeps current state synchronized. The implementation and automated release
evidence are recorded in the [implementation evidence](v0.1.3-implementation-evidence.md).

This document owns product scope and acceptance. The
[compatibility baseline](v0.1.3-baseline.md) records the verified v0.1.2
dependency used by the implementation. The
[technical design](v0.1.3-technical-design.md) owns domain, schema, service,
history, and Fyne contracts. The
[implementation plan](v0.1.3-implementation-plan.md) owns delivery order.

The archived Rust/Tauri v0.1.3 documents were used as design input only. Their
professional ledger vocabulary, implementation status, schema numbers, IPC,
and release evidence do not apply to Nestworth-go.

## Release Goal

A Household can answer three ordinary questions:

1. What changed?
2. Which Account or investment did it affect?
3. How has our recorded net worth changed since we started tracking it?

The central invariants are:

> Moving money or an investment between Household Accounts does not become new
> income or spending.

> Existing v0.1.2 state becomes a clearly labeled history starting point, not a
> fabricated deposit, purchase, or transfer.

> The interface uses family language. Internal Activity legs, projection
> observations, replay, dirty dates, and snapshot revisions are implementation
> details and are never user inputs.

## Family-First Experience Principles

- Start with **What happened?**, not accounting terminology.
- Prefer one short form with sensible defaults over a multi-step ledger editor.
- Default date and time to now; show backdating only as an optional field.
- Show a plain-language preview such as “Savings decreases by 2,000 CNY;
  Brokerage cash increases by 2,000 CNY.”
- Use **Undo** and **Fix entry**, not “post reversal” and “correction chain.”
- Use **Start history here**, not “initialize History Origin.”
- Use **History is updating** and **Some values are missing**, not rebuild
  cursors, revisions, coverage algorithms, or dirty ranges.
- Keep technical details available only as read-only provenance where they help
  explain a value.

## Baseline and Dependency

The implementation depends on the completed v0.1.2 contracts for:

- schema `3` Instruments, Holdings, investment cash, quotes, and preferences;
- exact Quantity, UnitPrice, FxRate, and Money strings;
- one current `ValuationService` shared by Overview, Accounts, and Investments;
- append-only Account Value, cash, Instrument Quote, and FX Quote observations;
- partial valued subtotals with explicit completeness;
- explicit Manual/Provider quote selection;
- current Yahoo refresh that never runs from ordinary reads.

v0.1.3 implementation may begin only after Phase 0 revalidates those contracts
against the actual completed v0.1.2 code and fixture. The planned v0.1.3
migration is schema `3 -> 4`; it must be renumbered if the implemented v0.1.2
baseline differs.

## User Stories

- As a Household member, I can start trustworthy history from the state already
  in Nestworth without inventing how we acquired it.
- As a user, I can record money added, money removed, a transfer, an investment
  purchase or sale, a value update, borrowing, or debt repayment.
- As a user, I can move cash across currencies by entering what left and what
  arrived without calculating an FX rate myself.
- As an investor, I can enter shares or units, total trade amount, and an
  optional fee without learning tax-lot or performance concepts.
- As a user, I can see a friendly preview before saving and current resulting
  balances after saving.
- As a user, I can undo an entry or fix it without losing the original audit
  trail.
- As a user, I can browse a Household timeline and one Account's history.
- As a user, I can view a net-worth trend with clear missing-value markers.
- As an offline user, I can record every v0.1.3 event and rebuild history
  without a provider request.

## Included

### Start History

- One immutable history starting point per Household.
- Existing users see a single setup card explaining that Nestworth will remember
  the current state from now onward.
- The resolved Household timezone is preselected; the user confirms it before
  history starts. No accounting or migration choices are shown.
- Current Accounts, values, Holdings, investment cash, financially relevant
  Account state, Ownership, and quote preferences are captured atomically.
- Captured starting values are labeled **Starting point**, never as income,
  spending, purchase, borrowing, or transfer.
- Fresh onboarding creates an empty starting point using the confirmed Household
  timezone.

### Record a Change

The primary action is **Record change** with these choices:

| User-facing choice | Typical use |
| --- | --- |
| Money added | Salary, investment income, contribution, gift, refund, or other inflow |
| Money removed | Material spending, withdrawal, tax, fee, or other outflow |
| Move between Accounts | Cash transfer, cross-currency transfer, or investment transfer |
| Buy or sell an investment | Shares or units plus total trade amount and optional fee |
| Update a value | Reconcile a balance, property/manual value, debt balance, or investment amount held |
| Borrow or repay debt | Paired liability and cash principal, plus optional repayment interest/fee |

Forms never expose raw legs, debit/credit, external-flow flags, projection rows,
or snapshot controls. Go derives and validates them.

### Friendly Classification

- Money added asks for a short reason: `income`, `contribution_or_gift`, or
  `other`.
- Money removed asks for `expense`, `fee_or_tax`, or `other`.
- Transfers and trades are internal movement, not income or spending.
- Value updates are reconciliations, not cash flow.
- Borrowed and repaid principal is separate from repayment interest or fee.
- Optional notes remain bounded and local.

These stable reasons support later analysis but are presented as ordinary
labels, not professional accounting categories.

### Transfer and Trade Workflows

- Same-currency cash transfer uses one amount and exact matching currency.
- Cross-currency transfer asks only **Sent** and **Received** amounts. Go derives
  and stores the transaction rate from destination/source.
- Investment transfer moves the same investment and exact number of shares or
  units between two Investment Accounts.
- Buy/Sell asks for shares or units, gross trade amount before fee, settlement
  cash, and optional explicit fee. Go derives the effective unit price.
- Settlement currency equals the Instrument quote currency in v0.1.3.
- Every accepted change keeps balances, investment cash, debt, and investment
  amounts non-negative.

### Undo and Fix

- A saved entry is never edited or deleted in place.
- **Undo** records the exact opposite effects, normally at the current time.
- **Fix entry** opens the original friendly form, saves an inverse plus corrected
  replacement atomically, and shows one simple “Corrected” relationship.
- If later changes make an undo unsafe, Nestworth explains which Account lacks
  enough balance or investment units without exposing internal legs.

### Household History

- Top-level **History** page with two simple views: **Timeline** and
  **Net worth**.
- Timeline defaults to recent entries and offers Account, change type, and date
  filters.
- Account detail includes entries that touched that Account and the Starting
  point marker.
- Overview includes a compact trend; History offers 30-day, one-year, and all
  available ranges.
- Closed local days use persisted local snapshot cache; the current day uses
  live v0.1.2 ValuationService output.
- Missing price or FX input produces a partial value with a clear **Missing
  value** marker and a direct action to add a dated manual quote where possible.
- An accessible table/list accompanies every chart.

### Automatic Local History Maintenance

- Saving a backdated change, dated quote, preference change, Ownership change,
  or valuation-relevant archive/state change marks internal history work.
- After current data is saved, a cancellable foreground worker updates closed
  days while the relevant view remains open.
- The user sees only updating, complete, partial, or failed/retry states.
- Current Overview and all local editing remain available while history updates.
- Rebuilding history performs no network request and never starts Yahoo refresh.

## Excluded

v0.1.3 does not implement:

- tax lots, lot selection, cost basis declarations, realized/unrealized gain;
- TWR, XIRR, benchmarks, attribution, or investment-performance claims;
- budgets, expense categories, receipt capture, or daily spending analytics;
- automatic interpretation of market movement versus FX movement;
- historical Yahoo backfill, OHLCV, corporate actions, dividends/splits from a
  provider, or automatic symbol resolution;
- short positions, negative cash, margin, options, derivatives, or leverage;
- cross-currency investment settlement or cross-currency debt principal;
- recurring/pending changes, scheduled posting, reminders, or approval queues;
- statement import, CSV import/export, backup/restore UI, sync, or collaboration;
- bank, broker, wallet, or exchange synchronization;
- background work while Nestworth is closed;
- permanent deletion or in-place editing of saved financial changes;
- a professional journal, raw double-entry editor, or configurable accounting
  chart of accounts.

## Locked Product Decisions

| Decision | v0.1.3 contract |
| --- | --- |
| Product tone | Family timeline; professional ledger vocabulary stays internal |
| Saved fact | Immutable internal Activity plus validated typed effects |
| Existing state | One Starting point; zero fabricated changes or pre-start trend |
| Start time | Existing user confirms “start now”; no claim that current state existed earlier |
| Timezone | Confirmed IANA Household timezone; immutable after first saved change |
| Event time | Defaults to now; optional past local date/time; no future or pre-start entry |
| Current mutation path | After history starts, every financial amount/Quantity change routes through Record change |
| Value update | User enters the new absolute value; Go persists a derived additive effect |
| No-change update | Rejected without creating a saved entry |
| Transfer | Internal and zero external flow; cross-currency rate derived from Sent/Received |
| Trade input | Quantity + gross total + optional fee; Go derives unit price |
| Trade settlement | Instrument quote currency only |
| Fee | Explicit and separately classified; never inferred from transfer spread |
| Negative state | Rejected for balances, investment cash, debt principal, and Quantity |
| Correction | Undo or atomic Fix entry; no edit/delete |
| Historical valuation | Never selects a quote after the historical cutoff |
| Missing input | Keep partial subtotal, mark incomplete, never substitute zero/one |
| History cache | Internal append-only revisions; UI shows only latest point/status |
| History maintenance | Automatic foreground local work; retry only after failure |
| Network | No Activity/history operation contacts a provider |
| Financial authority | Go services; Fyne formats results and chart geometry only |

## Acceptance Scenarios

### Move Money Without Creating Income

Starting state:

```text
Family savings = 10,000 CNY
Broker cash    =      0 CNY
Net worth      = 10,000 CNY
```

Record **Move between Accounts** for `3,000 CNY`:

```text
Family savings = 7,000 CNY
Broker cash    = 3,000 CNY
Net worth      = 10,000 CNY
Income/spending effect = 0
```

One save atomically records both sides and resulting current state.

### Buy an Investment With a Fee

An Investment Account has `1,000 USD` cash. The user records:

```text
Buy QQQ
Shares/units       = 2
Trade amount       = 200 USD
Fee                = 5 USD
```

Nestworth previews and saves:

```text
Cash after purchase = 795 USD
QQQ shares/units    = 2
Derived unit price  = 100 USD
Fee                 = 5 USD
```

At a `100 USD` selected QQQ quote, Account value is `995 USD`. The trade
principal is internal; only the explicit fee explains the five-dollar decrease.

### Cross-Currency Family Transfer

The user enters **Sent `100 USD`** and **Received `690 CNY`**. Nestworth derives
`1 USD = 6.9 CNY`. It does not ask for an FX-rate formula. The entry remains an
internal transfer. A read-only detail may later show conversion difference
against a historical market quote; absence of that quote never blocks saving.

### Start From Existing Family State

A v0.1.2 Household already has `3 QQQ` and `5,000 SGD` cash. The user confirms
**Start history here**. Nestworth captures that state once, creates no purchase,
deposit, or transfer, and shows no trend before the Starting point.

### Fix an Entry

The user saved Money added as `5,000 CNY` but meant `500 CNY`. **Fix entry**
prefills the friendly form. Saving records the internal inverse and corrected
replacement together. The timeline shows one corrected entry and retains an
expandable link to the original; current state changes by `-4,500 CNY` exactly.

### Incomplete History

A closed day contains QQQ units but no selected QQQ quote at or before its
cutoff. The point shows its valued subtotal and **Some values are missing**.
QQQ is not zero. Adding a dated manual QQQ price updates affected closed days in
the foreground and preserves prior internal snapshot revisions.

## Release Acceptance

v0.1.3 is development-complete only when:

- Phase 0 freezes the actual completed v0.1.2 schema-3 fixture, APIs, goldens,
  query bounds, and Fyne ownership before schema-4 work starts.
- Migration `3 -> 4` preserves every v0.1.1/v0.1.2 identity, observation,
  selected current value, quote preference, archive state, and future-schema
  zero-write/no-network guarantee.
- Existing Household initialization is explicit, atomic, idempotent, and creates
  zero Activities; partial initialization blocks financial mutation safely.
- Fresh onboarding creates one empty Starting point with a confirmed timezone.
- Every user-facing change type builds only its approved internal shape and
  updates all current projections in one transaction.
- New Account/Holding starting amounts after history begins receive an explicit
  family-facing explanation and cannot bypass HistoryService.
- Value updates persist derived additive effects; no-change submissions write
  nothing; no resulting endpoint becomes negative.
- Same-currency, cross-currency, and investment transfers remain internal and
  atomic; derived transaction FX retains both native amounts.
- Buy/Sell retains Quantity, gross total, derived unit price, settlement
  currency, and explicit fee without exposing cost-basis concepts.
- Undo/Fix preserves original evidence, rejects unsafe replay, and updates
  current state and history atomically.
- Timeline ordering and cursor pagination are deterministic and bounded.
- Historical reconstruction starts from the Starting point, applies ordered
  saved effects, uses effective state/preference, and never selects a future
  quote.
- Closed-day cache revisions retain exact component/quote provenance; unchanged
  rebuilds do not append duplicate revisions.
- History work is pending only when the earliest affected date is a closed day;
  a change affecting today alone does not create false remaining work.
- Foreground history maintenance is cancellable/resumable, never blocks current
  Overview, and makes zero provider calls.
- Timeline and trend present simple language, incomplete states, keyboard
  operation, accessible alternatives, and paired English/Simplified Chinese
  strings.
- Fyne performs no balance, trade, FX, net-worth, replay, or snapshot arithmetic.
- Domain, migration, initialization, transaction, replay, history, query-bound,
  UI, locale, race, golden, and compatibility tests pass through the normal Go
  repository gates.
- Isolated-data launch, arm64 packaging, keyboard/VoiceOver, signing, and
  notarization remain named release checks and are never implied by unit tests.

## Compatibility Promises

v0.1.3 preserves every active v0.1.1 and approved v0.1.2 promise and adds:

- Activity, effect, Starting point, state-observation, and historical snapshot
  identities remain stable typed UUIDs.
- Starting point components and saved Activities are immutable evidence.
- A starting or reconciled investment Quantity never becomes a fabricated Buy
  or assigned acquisition cost in a later release.
- Internal transfers remain distinguishable from money entering/leaving the
  Household.
- Trade Quantity, gross total, derived unit price, settlement currency, and
  explicit fee remain available for later optional analytics.
- Undo/Fix relationships remain resolvable after Account or Instrument archive.
- Current projection tables may be optimized, but persisted event effects and
  classifications may not be reinterpreted.
- Historical snapshot cache remains separate from event facts; recalculating a
  value never rewrites what the user recorded.
