# v0.3.0 Release Contract

## Status

`0.3.0` is the current unreleased development line (build `1`). Public
publication is not implied by synchronized local metadata. The `0.2.1` line
is superseded and was never published.

## Release goal

Keep the Wails v3 local-first desktop, with Go as the sole financial
authority, and add recoverable local backup/restore plus create-only CSV
import/export for Accounts and Holdings. The business SQLite schema remains
`9`.

## Included capability

Everything in the `0.2.1` desktop surface, plus:

- Settings Data management: back up data, restore from backup, import/export CSV;
- `.nestworth-backup` ZIP with `manifest.json`, `database.sqlite`, and
  `settings.json`; snapshot via `VACUUM INTO`; owner-only files;
- Restore preview, typed `RESTORE` confirmation, journaled file-group swap,
  quit and relaunch, rollback of an unverified replacement;
- Blocked-startup restore through always-registered `RecoveryService`;
- Accounts and Holdings CSV export/import with mapping, preview, error CSV,
  and one atomic create-only commit;
- Last-backup summary in `.nestworth-backup-status.json` next to the live
  database (filename only).

## Non-goals

This release does not include cloud backup, scheduled backup, backup
encryption, synchronization, direct bank/broker integrations, background
refresh, CSV of Activities or History Origin, CSV update/delete, schema `9`
tables for import, in-process session swap after restore, signing,
notarization, or public artifact publication.

## Technical invariants

- The frontend does not open SQLite, issue HTTP requests, or recalculate
  authoritative financial values.
- Financial values cross the Wails boundary as lossless decimal strings and
  typed wire DTOs.
- Multi-entity mutations are validated and committed atomically.
- Posted financial changes are immutable; corrections and reversals append
  linked facts.
- Missing quotes or missing instruments produce an explicit incomplete result
  and are never silently replaced with zero.
- Database compatibility and integrity are checked before business writes.
  Incompatible files, including schemas `6`, `7`, and `8`, must be replaced
  by creating a new database or restoring a schema `9` backup.
- Restore never copies a live main SQLite file; it checkpoints, closes, and
  moves the file group. CSV observation times come from CSV dates, not
  `clock()`.

## Acceptance checks

The automated closeout is:

```bash
GOCACHE=/tmp/nestworth-go-0.3.0 go test ./...
GOCACHE=/tmp/nestworth-go-0.3.0 go test -race ./...
GOCACHE=/tmp/nestworth-go-0.3.0 go vet ./...
gofmt -l cmd internal
go build ./cmd/nestworth
cd frontend && pnpm run lint && pnpm run typecheck && pnpm run test
git diff --check
```

The packaging smoke target is:

```bash
wails3 task darwin:package:release
```

The resulting local artifacts should identify as `0.3.0`, build `1`, bundle
ID `com.nestworth.app`, and arm64 on the primary target. Manual keyboard and
accessibility review, signing, notarization, and artifact retention must be
reported separately from automated checks.

## Completion rule

The release is ready for publication only when the included capability is
covered by code and relevant tests, all synchronized metadata reports
`0.3.0`, the packaging smoke is independently inspected, and every remaining
manual gate is either completed or explicitly accepted by the release owner.
