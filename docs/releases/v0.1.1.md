# v0.1.1 Release Contract

## Purpose and Status

**Release theme:** Build the Household balance sheet.

**Status:** `Core implementation complete; public-release closeout pending`.

This is the active Go + Fyne contract for the v0.1.1 implementation in
Nestworth-go. The original mixed document, including unverified Rust/Tauri
phase and release evidence, is retained only in the
[unreviewed archive](../legacy/rust-tauri-inherited-unreviewed/releases/v0.1.1.md).

## Release Goal

A user can create one local Household, record who owns each Account, maintain
assets and liabilities with exact current values, and see an authoritative
current net worth without registration or a network dependency.

## Implemented Scope

### Household and References

- Atomic create-once Household onboarding with one immutable base currency.
- One or more Members and an invariant that at least one active Member remains.
- Institution and Group management.
- Archive and restore with retained-reference behavior.
- Household-scoped normalized Member avatars and Institution/Group logos.

### Accounts and Values

- Cash Equivalent, Investment, Property, Receivable, and Liability Accounts.
- Balance and Manual Value tracking according to Category policy.
- Immutable TrackingMode and default currency after Account creation.
- Exact Ownership in integer basis points totaling 10,000.
- Optional Institution, Group, note, icon/logo, dates, and inclusion flags.
- Append-only Account Value observations with deterministic latest selection.
- Create, list, detail, update, append value, archive, and restore workflows.
- Intersecting Account filters by Member, Institution, Group, Category, and
  sole/shared Ownership scope.

### Overview

- Account count, assets, liabilities, and net worth.
- Breakdown by Category, Member, Institution, and Group.
- Go application-layer financial authority under one consistent SQLite read
  snapshot.
- Non-negative stored liabilities whose sign comes from Category.
- Archived and excluded Accounts omitted from authoritative totals.

### Application Experience

- Fyne onboarding, live navigation, Overview, Account/reference management, and
  Settings surfaces.
- English, Simplified Chinese, and Traditional Chinese catalogs where currently
  supported by the settings contract.
- System, Light, and Dark appearance plus persisted window size.
- Bounded local image normalization and storage.
- Loading, validation, empty, conflict, and blocked-startup states.

### Persistence and Compatibility

- Local SQLite bootstrap with foreign keys, bounded busy timeout, integrity
  verification, and a single writer connection.
- Ordered schema migration through current schema version `2`.
- Recoverable `VACUUM INTO` sibling snapshot before migrating an existing older
  database.
- Unsupported future schema blocks startup before application business writes.
- No automatic deletion, replacement, or recreation after open, migration, or
  integrity failure.

## Excluded

v0.1.1 does not implement:

- Holdings Account creation or Holding management;
- Instruments, investment cash, Instrument prices, FX quotes, or FX conversion;
- Activity, transfers, trades, history, analytics, cost basis, or performance;
- provider integrations, background refresh, bank/broker synchronization;
- backup/restore UI, import/export, cloud sync, or permanent deletion.

Schema/domain placeholders or navigation labels for later releases do not make
those features part of v0.1.1.

## Locked Contracts

| Decision | v0.1.1 contract |
| --- | --- |
| Household | Exactly one local Household |
| Base currency | Immutable after onboarding |
| Identity | Distinct lowercase UUID v7-backed domain ID types |
| Money | Canonical non-negative decimal text; no binary floating point |
| Liability sign | Derived from Category, never persisted as negative Money |
| Ownership | Integer basis points totaling exactly 10,000 |
| Account Value | Append-only observation; latest by effective time, creation time, then ID |
| TrackingMode | Immutable after creation |
| Archive | Reversible; no permanent-delete workflow |
| Financial authority | Go application/domain services; Fyne formats results |
| Startup failure | Preserve the database and block business workflows safely |
| Network | No dependency for any v0.1.1 workflow |

## Development Acceptance

The implemented scope remains accepted only while current tests prove:

- onboarding is atomic and rejects a second Household;
- Account creation/update validates Category, TrackingMode, currency, exact
  Ownership, dates, active-new references, and initial Money atomically;
- archived references can be retained but not newly selected;
- Account Values remain append-only and deterministic;
- Overview totals and breakdowns agree with the application golden fixtures;
- unsupported future databases receive no persistent application writes;
- database migration/reopen, foreign-key, and integrity checks pass;
- UI localization, settings, media bounds, form preservation, and primary
  keyboard flows remain covered;
- `go test ./...`, `go vet ./...`, formatting, and `git diff --check` pass.

## Public Release Closeout

Before a normal public release, record rather than assume:

- isolated-data launch from the built `.app` and mounted `.dmg`;
- keyboard and physical VoiceOver smoke results;
- exact arm64 packaging output and checksum;
- Developer ID signing, signature verification, notarization, and stapling when
  required by the selected distribution policy;
- final version/changelog synchronization, annotated tag, and artifact identity.

An unsigned build may be shared only when clearly labeled as a controlled-test
artifact.

## Compatibility Promises

Later releases must preserve:

- typed Household-scoped identities;
- exact Ownership and non-negative Money semantics;
- append-only Account Value evidence;
- immutable Account TrackingMode/default currency;
- archive and retained-reference behavior;
- Go authority for persistence and financial calculations;
- safe future-schema blocking and recoverable migrations;
- complete local usability when optional integrations fail.
