## Saved implementation

`WithReviewNoChangeCandidate` opts a repository into an experimental no-change
confirmation; ordinary repositories and `WithFullReviewRecompute` disable it.
The shared reconcile service attempts confirmation under its ledger write
coordination, otherwise follows the full C2 capture/prepare/publication path.
Changed-source publication still retains every full source recheck.

Confirmation holds the existing driver's immediate write reservation throughout.
It checks the schema cookie recorded at verified open, FK/recursive-trigger
settings, C1 trigger definitions and bounded journal integrity, source and
control/state/rule revisions, the C2 temporal certificate and closed-day vector,
review configuration/open-episode metadata fingerprint, FX provider selection,
and the final injected clock. Control/checkpoint CAS require one affected row;
only checkpoint metadata changes, without daily evidence writes. The opt-in
full publication mints the added proof in existing certificate JSON; old C2
certificates cannot authorize confirmation. Any DDL after open disables reuse
for that handle, including trigger drop/recreate around untracked DML.

Main additions: `internal/infrastructure/sqlite/review_no_change.go`,
`internal/domain/review_no_change.go`,
`internal/application/review_no_change_test.go`. Existing capture, financial
algorithms and full-source publication checks are retained. Small changes also
bind `ReviewPublication.FXProviderKey` and the optional proof fields, integrate
the shared service, and record the verified-open schema cookie.
