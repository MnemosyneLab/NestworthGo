## Findings, console and network

**P2: investment-review preview fails to replay an accepted contribution→buy history.** On a fresh synthetic household with History origin Oct 1, create a brokerage account, add `$2,000`, then buy 10 units at `$100` each with a `$5` fee. Import valid daily NAVs through Oct 17. In Investment Review create a `Meet all` rule with `Holding amount > USD 900` and `Cost > USD 1,002`, then Preview. The app shows `Amount: The history could not be updated.` and the real backend returns 422; server logging reports `history_update_failed` / `historical replay reached a negative balance` from historical replay. The account cash after the buy is `$995`, so this does not reflect a genuinely negative ending cash balance. It reproduced across three isolated UI fixture orderings and blocks review analysis for this ordinary accepted ledger. Suggested fix: inspect cash effect/baseline ordering in replay and add a regression using the exact contribution and fee-bearing buy events; ensure review preview preserves the valid closing cash balance.

**Low severity (P3): missing favicon.** Each new page requested `GET /favicon.ico`, which returned 404 and produced a Chromium console error. The UI otherwise loaded and operated; successful browser flows had no unexpected API failures or page exceptions. Suggested fix: serve the app icon at `/favicon.ico` or remove the request if the HTTP server does not provide one.

Other observed HTTP 422 responses were expected validation/precondition paths: zero-value preview, negative manual quote, missing History on the review fixture before starting it, archiving an instrument with a holding, and attempting an earlier History Origin with already-present holdings. Each displayed an error state. The held-instrument archive conflict and earlier-origin conflict are not reported as product defects. The contribution→buy review-preview 422 is unexpected and is the P2 defect above. Successful transaction previews and confirmations returned normally. Aside from this defect and the repeated favicon 404, there were no page exceptions or unexpected failed browser requests.
